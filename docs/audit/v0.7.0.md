## 1. 요약

1. **어시스턴트로 설정을 바꿀 수 없습니다**(USR-1, 사용자 PC 보고). 원인을 찾았습니다. 플랜 문법이 JSON 키를 알파벳순으로 강제하기 때문에, 모델이 `"op"`부터 쓰기 시작하면 `set_setting`을 고를 수 없고 `set_profile`·`set_theme` 같은 op만 남습니다(PLN-1). 설정 op가 확인 없이 바로 실행되는 것과 겹쳐 "배율 130"이 "프로파일: 균형"으로 실행됩니다. 같은 깔때기에 op 24개가 걸려 있어, 0.6.0의 "어시스턴트가 모든 기능 수행"이 실제 모델에서는 넓게 깎였을 가능성이 있습니다(실모델로는 이 환경에서 확인하지 못함).
2. **명령이 아닌 말과, 표현할 칸이 없는 요청을 다루지 못합니다**(USR-6·USR-7, 사용자 PC 보고). 인사에는 빈 플랜 카드가 뜨고, "프로젝트 별 요약"은 전체 요약으로 바뀌어 바로 실행됩니다. 두 경우 모두 모델은 뜻을 알아들었습니다. 플랜에 글로 답하는 칸과 묶는 기준이 없고, 못 하는 요청을 되묻는 규칙이 없습니다. 모델 경로의 정확도를 재는 평가도 없었습니다(PLN-21).
3. **설정 일부가 저장되지 않습니다**(USR-4). 설정 > 참고 자료 전체와 문서 생성 토큰 상한이 앱을 켤 때마다 기본값으로 돌아갑니다.
4. **0.7.0의 3번(문서 작성 화면 스크롤)은 덜 고쳐졌습니다**(UI-1). 미리보기 위에서 휠을 굴리면 창 전체가 밀립니다. 배율 150 %나 작은 창에서는 **대화상자의 버튼이 화면 밖**으로 나가 프로젝트를 만들 수 없습니다(UI-3).
5. **확인 없이 검토 결과를 덮어쓰는 경로가 여럿입니다.** 어시스턴트의 추출(PLN-3), 이름만 바뀐 문서의 자동 재추출(PIP-1), 검토함의 재추출·양식 테스트(PIP-2), 취소한 초안 작업(GEN-3), 결과 카드의 옛 스냅샷(GEN-4).
6. **아예 되지 않는 기능**: `&` 뒤에 한글이 오는 HTML 변환 패닉(DOC-1), 목록 블록 입력(GEN-5), 보완요청서의 초안 어시스턴트(GEN-1), 이미 등록된 파일을 프로젝트에 끌어다 놓기(PRJ-1), 모델 폴더 가져오기(PLT-12), 어시스턴트의 검토 값 수정(PLN-8).
7. **배포**: CUDA 재배포 자산이 저장소가 스스로 전제로 적은 앱 EULA 없이 게시되어 있고(PKG-1, 결정 필요), 설치파일에 들어가는 고지문의 모델 항목이 아직 Qwen·bge입니다(PKG-2).
8. **기준선은 정상입니다.** `main`과 0.7.1 범프 커밋의 CI 7개 잡이 모두 통과했고, 화면 순회 중 콘솔 오류와 번역 키 노출은 없었으며, 화면↔코어 명령 180개의 이름·인수가 일치했습니다(§14).

1. **기준선**: `main` dbb598e(run 42938205630)와 0.7.1 범프 16c9067(run 42938573265)의 CI 7개 잡.
2. **화면 순회**: 브라우저 빌드(모의 백엔드)를 Playwright로 돌며 온보딩부터 문서함·뷰어·어시스턴트·검토함·문서 작성·프로젝트·정리·작업 현황·설정 7개 탭·명령 팔레트까지 조작했습니다. 19개 화면은 배율 100·120·150 %로, 대화상자는 150 %와 최소 창(960×600)으로 다시 열었습니다. 화면마다 문서 루트 넘침, 가로 넘침, 글자 줄 수, 접근성 이름, 콘솔 오류, 번역 키 노출을 자동으로 재고 스크린샷 128장을 남겼습니다.

## 3. USR — 사용자가 보고·지시한 항목 (7건)

2026-11-11에 받은 스크린샷 네 장(어시스턴트의 설정 명령, "유형 → 추출 항목 매핑" 패널, 인사말, "프로젝트 별 요약")과 그 원인을 쫓다 나온 항목입니다. USR-1의 근본 원인은 PLN-1입니다. USR-6·USR-7은 모델이 뜻을 알아들었는데 플랜에 그 답을 담을 칸이 없어 생깁니다.

- [ ] **USR-1** `A` 어시스턴트로 설정을 바꾸면 엉뚱한 설정이 확인 없이 실행된다
  - **문제** 어시스턴트로 설정을 바꿀 수 없음(2026-11-11 스크린샷, gemma4-e4b-q4km): "UI 배율 120%"·"배율을 130 으로 변경해줘" → "프로파일: 균형", "DPI 를 200 으로 변경해줘" → "테마를 '시스템'(으)로 변경했습니다"가 확인 없이 실행됨. 원인은 네 겹이다. ① **PLN-1**(결정적): 문법 스키마의 키가 알파벳순으로 강제되어 `set_setting`은 `"key"`로 시작해야만 쓸 수 있고, 모델이 (설정 계열의 유일한 예시인 `set_theme`처럼) `"op"`부터 쓰면 `set_profile`·`set_theme`만 남는다. ② 모델 우선 모드에서는 슬래시 명령 말고는 규칙을 전혀 쓰지 않고, 모델이 고른 설정 op가 문장과 관련 있는지 검사하지 않는다(PLN-2). ③ 설정 op는 확인 카드 없이 모델의 자기 신뢰도(0.95)만으로 즉시 실행된다. ④ 프롬프트에 `set_setting` 예시가 없고 46개 키가 영문 경로 한 줄(1,233자)로만 제시된다(한국어 라벨 없음, PLN-9). 근거 수준: 문법의 강제 순서는 실험으로 확인했고, 실기 증상(설정 문장이 `set_profile`·`set_theme`으로만 빠짐)이 그 깔때기에 남는 op와 일치한다. 실제 Gemma 모델로 이 환경에서 재현한 것은 아니다.
  - **수정** PLN-1을 먼저 고친다(문법에서 `op`가 항상 첫 키). 그 위에: 설정 문장은 설정 카탈로그(라벨·별칭·동의어 + 값)로 결정적으로 먼저 해석하고 모델은 나머지만; 모델이 만든 설정 변경은 규칙 결과와 다르면 규칙을 따르거나 확인 카드로; 실행 결과에 "이전 값 → 새 값"과 되돌리기 버튼; `set_setting` 한국어 예시 2\~3개와 `키=라벨` 표를 프롬프트에 추가; 실모델 회귀 테스트(문법을 켠 llama-server로 설정 문장 10여 개).
  - **위치** `planner/schema.rs:662` · `llm.rs:103` · `prompts.rs:476` · `AssistantPage.tsx:373` — 확인: 사용자 PC 보고 · 실험 재현
- [ ] **USR-2** `B` '규칙' 해석 모드도 짧은 설정 문장을 알아듣지 못한다

- [ ] **USR-6** `B` 명령이 아닌 말(인사·잡담·일반 질문)에 답하는 길이 없다
