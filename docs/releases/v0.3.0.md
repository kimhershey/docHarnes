# DocuLens 0.3.0

v0.2.0(2026-11-09) 이후의 변경 사항입니다. 설치·실행 방법은 [docs/RUN-GUIDE.md](https://github.com/kimhershey/docHarnes/blob/v0.3.0/docs/RUN-GUIDE.md), 사용자 PC에서 확인할 항목은
[docs/user-pc-checklist.md](https://github.com/kimhershey/docHarnes/blob/v0.3.0/docs/user-pc-checklist.md)의 "0.3.0" 절을 보세요. 이 판은 **Lite 설치파일만** 배포합니다.

## 설치파일

| 파일 | 내용 |
|---|---|
| `DocuLens-Setup-Lite-0.3.0-x64.exe` | 앱 + llama-server CPU·Vulkan 엔진 팩 + PDFium + ko-dic (약 50 MB) |
| `*.sha256` | 설치파일의 SHA-256 — `certutil -hashfile DocuLens-Setup-Lite-0.3.0-x64.exe SHA256`으로 비교 |
| `THIRD-PARTY-NOTICES.md`, `sbom.cdx.json` | 제3자 고지와 CycloneDX SBOM |

- 모델(GGUF)은 설치파일에 들어 있지 않습니다. 첫 실행 뒤 모델 관리자에서 준비합니다.
- CUDA 엔진 팩과 Full 설치파일은 이번 판에 없습니다. v0.1.0의 `DocuLens-EnginePack-cu121-b12066.zip` / `-cu129-`를
  `%LOCALAPPDATA%\DocuLens\engines\b12066\` 아래에 풀면 그대로 쓸 수 있습니다(엔진 태그 b12066 동일).
- 사용자 단위 설치(관리자 권한 불필요), Windows 10 1803+/11 x64. 0.2.0 작업 공간은 열 때 자동으로 옮겨집니다(마이그레이션 0008·0009).

## 소프트웨어 개발 문서 중심으로

- **추출 스키마 내장 양식** — 제안요청서(RFP)·제안서·과업지시서·요구사항 정의서·소프트웨어 개발 계약서·WBS·일정표·진척 보고서·회의록·테스트 결과서·
  변경요청서·검수확인서·견적서(인력·MM 기준)·일반 13종. 0.2의 세금계산서·계산서·영수증·사업자등록증·계약서·신청서는 지우지 않고 **숨김**(양식 화면의
  "숨긴 기본 양식"을 펼쳐 다시 켤 수 있음). 새 검증 규칙(진척률·통과율 0~100, 총 케이스 = 통과+실패+보류). 라이브러리의 거래처·날짜·합계 열은
  수행사·제안사·발주기관, 계약일·회의일·테스트 일자, 제안 금액·사업 예산까지 채웁니다.
- **프로젝트 템플릿** — 외주 개발 사업(계약금액 = 제안 금액, ≤ 사업 예산, 과업 금액 ±5 %, 계약서·검수확인서 서명)·유지보수·내부 개발 3종.
- **문서 생성 템플릿** — 같은 12종 + 보완요청서. 개발 계약서는 제1조~제10조(지식재산권·하자보수·비밀유지·검수), 견적서는 역할·등급·투입 MM·단가·공급가액 표.
  0.2의 공문·거래명세서·구형 계약서/보고서/회의록/견적서 템플릿은 숨김(이름을 명시하거나 저장된 초안은 그대로 동작).
- **어시스턴트** — "개발 계약서 → 엑셀", "지난달 견적서 합계", "작년 개발 계약서 중 가장 큰 계약금액은?", "'위약금' 들어간 계약서 찾아줘",
  "이 견적서 합계 금액이 얼마야?"(열린 문서에 대한 답변), "10월 진척 보고서 써줘"를 맞게 해석합니다. 플래너 골든셋 100건을 SW 어휘로 다시 썼습니다.

## 문서 생성 토큰 예산 — 외주 규격 문서 한 통

- 생성 화면의 **토큰 예산** 컨트롤(길이 설정에 따름 / 2,600 / 6,000 / 12,000 / 24,000 "문서 한 통" / 직접 입력)과 모델 컨텍스트·상한·예상 시간 표시.
- 약 3,000 토큰(또는 컨텍스트의 35 %)을 넘는 예산은 **개요 → 절별 분할 생성**: 필드·표와 1절을 먼저 만들고 나머지 절은 앞 절 요약·확정 정보와 함께
  절마다 생성합니다(진행률 "n/m절", 취소하면 생성된 절까지 보존). 상한은 설정 > 처리 > 문서 생성에서 GPU 32,768(최대 65,536) / CPU 전용 8,192(최대 12,288).

## 프로젝트 — 날짜 기준 단계, 프로젝트별 정리·내보내기, 추적 사본

- 접수·추출·검증·보완요청·완료 상태 선택을 없애고 **시작일·종료일로 진행예정·진행중·완료**를 계산합니다. 종료일이 지났는데 필수 서류 누락·불일치가
  남았거나 검사 전이면 **"기한 경과"** 배지, 종료일이 없으면 진행중. "완료 처리"·"다시 열기"는 종료일만 바꿉니다.
- 프로젝트마다 **정리·내보내기 설정**(폴더·파일명 템플릿, 내보내기 형식·레이아웃·경로)과 "이 프로젝트 정리 / 내보내기". 템플릿 변수 `{{project}}`
  `{{project_code}}` `{{project_phase}}` `{{project_start}}` `{{project_end}}` `{{project_owner}}`, 폴더 프리셋 "프로젝트별", 엑셀 "프로젝트별 시트"
  (CSV는 프로젝트별 파일), 집계 "프로젝트별".
- 한 문서를 여러 프로젝트에 넣으면 두 번째 프로젝트부터 그 프로젝트 폴더에 **실제 사본**이 생기고 추적됩니다(문서 레코드는 하나; 재검사 때 다시
  등록되지 않음, 원본이 바뀌거나 옮겨지면 따라감, 밖에서 고친 사본은 "원본과 다름"으로 표시 → "다시 동기화", 프로젝트에서 빼면 사본 삭제).

## 양식 등록 — 문서 1~N개에서 스키마 자동 도출

- 샘플 문서 여러 개(라이브러리 선택 → "선택 문서로 양식 만들기", 끌어다 놓기)로 작업이 문서마다 필드를 찾아(오피스 양식은 표 구조, 스캔·PDF는 모델,
  모델이 없으면 텍스트 규칙) 하나의 스키마로 병합하고, 결과는 **저장되지 않은 초안**으로 편집기에 열립니다.
- 저장은 편집기의 저장 버튼으로만. 같은 이름의 스키마가 있으면 "이름 (2)"를 제안하는 팝업이 뜨고, 바꾸기 전에는 저장할 수 없습니다.

## 뷰어 — 글자 수정 이력과 되돌리기

- 페이지 글자를 고친 기록이 쪽마다 남고(최근 50건), 뷰어에서 **Ctrl+Z는 그 쪽의 글자 수정을 먼저 되돌리고** Ctrl+Shift+Z로 다시 적용합니다. 되돌릴
  글자 수정이 없을 때만 Ctrl+Z가 파일 정리 배치를 되돌립니다(0.2.0의 "되돌리기가 동작하지 않음" 보고 해결).
- 레이어 바의 "수정 n건" 버튼, 이력 탭의 "글자 수정" 목록과 "이 수정 되돌리기". 원본 파일은 바뀌지 않고, 되돌리면 검색 색인도 되돌아갑니다.

## 알려진 제약

- 실제 Qwen3.5-4B 모델 경로의 플래너 정확도·장문 생성 품질·다중 문서 스키마 도출은 이 저장소의 CI에서 측정하지 못합니다(가중치 없음).
  사용자 PC에서 `doculens-eval planner --engine …`과 체크리스트의 0.3.0 항목으로 확인합니다.
- 분할 생성의 예상 시간은 GPU 25 tok/s·CPU 6 tok/s 가정값이고, CPU 전용 PC에서 "문서 한 통"은 상한 8,192 토큰으로 줄어듭니다.
- 사본의 외부 변경은 재검사·"다시 동기화" 시점에만 감지합니다(폴더 감시 연동 없음). 프로젝트 템플릿 단위의 정리 설정 상속은 없습니다.
- UI 배율 150 %에 1280 px 폭 이하 창의 제약은 0.2.0과 같습니다.
