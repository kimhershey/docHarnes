## 1. AI 어시스턴트 — 문장을 읽는 방식

### 무엇이 잘못됐었나

0.7.0에서 "UI 배율 120%"는 모델 프로파일을, "배율을 130 으로 변경해줘"와 "DPI 를 200 으로 변경해줘"는 테마를 바꿨고, "안녕하세요."에는 빈 플랜 카드가,
"프로젝트 별 내용을 요약해줘"에는 전체 요약이 나왔습니다. 원인은 한 곳이 아니었습니다.

- **문법이 키 순서를 알파벳순으로 강제했습니다.** 플랜 JSON의 첫 키가 `clarification_question`·`confidence`가 되고, 단계의 종류(`op`)는 그 단계의 인수 뒤에 쓰게 되어
  모델이 "무엇을 할지"를 정하기 전에 값을 먼저 써야 했습니다. 이제 `summary → unmet → intent → scope → operations` 순서로, 단계는 `op`부터 씁니다
  (실제 llama-server에서 순서를 확인하는 테스트를 넣었습니다).
- **설정 값의 종류를 문법이 구분하지 않았습니다.** `set_setting`의 값이 아무 문자열이나 될 수 있어 "120"이 프로파일 이름 자리에 들어갔습니다. 이제 설정 키마다 값의 종류(정수·비율·켜짐/꺼짐·선택지)가 문법에 묶여 있습니다.
- **명령이 아닌 말과, 표현할 칸이 없는 요청을 받을 자리가 없었습니다.** 인사는 `noop` 플랜이 되고, "~별"은 버려졌습니다.
- **모델이 낸 플랜을 문장과 대조하지 않았습니다.** 문장에 없는 설정을 바꾸는 플랜도 신뢰도 숫자만 넘으면 바로 실행됐습니다.

### 이제 이렇게 동작합니다

- **설정 한 문장과 인사는 모델을 거치지 않습니다**(해석 방식 '모델'·'규칙' 모두). 문장 전체가 설정 하나를 말할 때만 해당합니다 — "UI 배율 120%", "배율을 130 으로 변경해줘",
  "DPI 를 200 으로 변경해줘", "다크 모드로 바꿔줘", "자동 임베딩 꺼줘". 질문("배율이 뭐야?"), 부정("바꾸지 마"), 다른 요청이 섞인 문장은 모델이 읽습니다. 카드의 출처는 "바로 해석"입니다.
- **설정을 바꾼 카드는 바꾸기 전 값과 새 값을 보여 주고 "되돌리기" 버튼이 있습니다.** 이미 그 값이면 "이미 200입니다"라고 답합니다. 단위도 읽습니다("5분" → 300초, "90%" → 0.9).
  범위를 벗어난 값은 되묻고, 그 되물음에 숫자만 답해도 이어집니다. 되돌리기는 그 뒤에 값이 다시 바뀌었으면 건드리지 않고 그렇게 알립니다.
- **인사·잡담·문서와 무관한 질문에 답합니다**(사용자 결정). 인사는 즉시, 잡담("넌 누구야?")은 한두 문장으로, 문서와 무관한 지식 질문("애자일 방법론이 뭐야?")은 모델의 일반 지식으로 답하고
  카드에 **일반 지식** 배지가 붙습니다. 그런 질문이라도 문서에 근거가 있으면 근거로 답하고 출처를 답니다. 이 경로는 설정 > 참고 자료의 "일반 지식 허용"이 꺼져 있어도 동작합니다
  (그 설정은 종전대로 "문서에 대한 질문인데 근거가 없을 때"에만 적용).
- **"프로젝트 별 / 유형별 / 폴더별 요약"은 묶음마다 요약 하나를 만듭니다.** 프로젝트에 들지 않은 문서는 "프로젝트 없음" 묶음으로 맨 뒤에 나옵니다. 본문이 없는 문서는 건너뛰고 몇 건인지 알립니다
  (전에는 한 건 때문에 전체가 실패). 현재 프로젝트를 열어 둔 채 "프로젝트별로"라고 하면 모든 프로젝트가 대상입니다.
- **모델이 낸 플랜은 문장과 대조합니다.** 아래 셋 중 하나면 바로 실행하지 않고 카드에 사유를 적어 승인을 기다립니다.
  - 요청 중 반영하지 못한 부분이 있을 때("…해서 메일로 보내줘" — 이 앱은 메일을 보내지 않습니다)
  - 문장이 나눠 달라고 하는데 그 기준으로 나눌 수 없을 때("담당자별로 요약")
  - 문장에 이름도 값도 없는 설정을 바꾸려 할 때, 또는 문장이 요청이 아니라 질문이나 알림일 때("DPI 200으로 바꿨어")
- 플랜이 대상 문서를 빠뜨렸는데 문장에 문서 유형이 하나 있으면 그 유형을 대상으로 넣습니다("배율 130으로 바꾸고 견적서 요약해줘" — 요약은 견적서만).
- **할 일이 없는 문장**에는 빈 플랜 카드 대신 한 줄로 답합니다.
- 오래 걸리는 작업(요약·OCR·추출)의 **자동 실행은 그대로 둡니다**(사용자 결정).

### 측정

- 골든셋 129 → **163문장**(사용자 PC에서 보고된 문장, 그 변형, 인사·잡담·일반 질문, 확인을 기다려야 하는 문장 34개 추가). 문장마다 종류(대화 5 · 질문 27 · 명령 100 · 설정 31)가 있고,
  "확인 없이 실행됐을 잘못된 변경" 건수를 따로 셉니다.
- 규칙 경로(모델 없이, 같은 채점): 0.7.0 140/163(확인 없는 잘못된 변경 6건) → 0.8.0 **154/163**(1건). 종류별 대화 2→4/5 · 질문 18→23/27 · 명령 98→98/100 · 설정 22→29/31.
- 실제 모델(Gemma 4 E4B Q4_K_M, CPU)로 두 판을 같은 23문장에 돌렸습니다(보고된 문장 5개 포함).

  | | 0.7.0 | 0.8.0 |
  |---|---:|---:|
  | 맞게 읽은 문장 | 4/23 | **20/23** |
  | 확인 없이 실행됐을 잘못된 변경 | 11건 | **0건** |

  0.7.0은 설정 문장 8개를 모두 테마·프로파일 변경으로 읽어 확인 없이 실행했고, 인사는 빈 플랜, "~별 요약"은 묶음 없는 요약이었습니다.
  0.8.0이 틀린 3문장은 "다크 테마 문서 찾아줘"(검색 대신 되물음 — 이 문장은 0.7.0보다 나빠짐), "DPI 200으로 바꿨어"(알림을 변경으로 읽지만 실행하지 않고 확인을 기다림),
  붙여 넣은 문장 다듬기(문서 초안으로 읽음 — 측정 뒤 검사를 넣었고 실제 모델로 다시 재지는 않음)입니다. 처음 측정에서 틀린 문장을 보고 검사 세 가지를 넣은 뒤 그 문장들을 다시 쟀습니다.
  문장별 결과와 다시 잰 내역은 [eval/results/planner-real-model](https://github.com/kimhershey/docHarnes/blob/v0.8.0/eval/results/planner-real-model/README.md)에 있습니다.
  **골든셋 163문장 전체가 아닙니다**(CPU에서 플랜 한 건에 수 분). 전체 측정은 GPU가 있는 PC에서 해야 합니다.
- 측정 방법과 다시 채점하는 스크립트는 [eval/README.md](https://github.com/kimhershey/docHarnes/blob/v0.8.0/eval/README.md)에 있습니다.

## 2. 0.7.0 점검 목록 처리

[docs/audit/v0.7.0.md](https://github.com/kimhershey/docHarnes/blob/v0.8.0/docs/audit/v0.7.0.md)의 153건(+ 작업 중 찾은 PKG-16)에 항목별 결과를 적었습니다.
**147건을 고쳤고, 4건은 일부만, 2건은 손대지 않았습니다**(아래 §4). 눈에 띄는 변화만 적습니다.

### 화면

- 창 전체가 스크롤되던 문제를 모든 화면에서 없앴습니다(문서 작성 미리보기 포함). 대화상자는 배율 150 %·최소 창에서도 닫기 버튼과 아래 버튼이 항상 보입니다.
- 어시스턴트 카드가 긴 경로에서 가로로 넘치지 않고, 문서함 목록 보기는 가로 스크롤이 없으며, 프로젝트 문서 표의 열이 눌리지 않습니다.
- 조사 "을(를)"·"(으)로"가 앞말에 맞게 표시됩니다. 토스트는 위쪽에 떠서 전송 버튼과 표의 버튼을 가리지 않습니다. 잘린 글에는 툴팁이 있습니다.
- 설정 > 양식·추출 항목의 "유형 → 추출 항목 매핑" 표에서 내장/사용자 열을 뺐습니다(사용자 결정).

### 어시스턴트 · 플래너

- 어시스턴트의 추출은 이미 추출·검토된 문서를 건너뜁니다("다시"라고 해야 다시 추출). "가져와서 …"의 뒤 단계는 방금 가져온 문서에만 적용됩니다.
- 프로젝트를 연 채 "새 프로젝트 만들어"는 문장이 가리킨 문서만 넣고, 문서를 지정하지 않은 프로젝트 명령은 되묻습니다. 되묻기에 "전부"로 답해 만든 플랜이 실행됩니다.
- 검토 값 수정·검토함 열기 명령이 동작합니다. 실패한 화면 동작은 카드에 실패로 남습니다. 편집한 플랜에 지운 날짜 조건이 되살아나지 않습니다.
- 질문에 날짜·유형·프로젝트 조건이 있으면 그 범위에서만 근거를 찾습니다. 범위에 문서가 없으면 전체에서 찾지 않고 "범위에 해당하는 문서가 없습니다"라고 답합니다.

### 설정 · 엔진 · 모델 · 작업 · 워크스페이스

- 설정 > 참고 자료 전체와 문서 생성 토큰 상한이 재시작 뒤에도 유지됩니다.
- 활성 모델 "자동"은 설치된 모델 중에서 고릅니다. 자동 백엔드는 내장 그래픽을 건너뛰고, Vulkan 로더가 없으면 Vulkan 팩을 시도하지 않습니다.
- 모델 폴더 가져오기가 동작하고, 받다 만 다운로드가 목록에 보이며, 내려받은 파일은 레지스트리의 SHA-256과 대조합니다.
- 초안 작업이 절 사이에 엔진을 놓아 주어 그 사이 어시스턴트가 답하고, 일시정지를 듣습니다. 일시정지한 대기 작업이 뒤 작업을 막지 않습니다.
- 워크스페이스 열기가 실패해도 열려 있던 워크스페이스는 계속 동작합니다. 종료할 때 잠금 파일을 지우고, **앱은 하나만 실행**됩니다(두 번째 실행은 이미 열린 창을 앞으로).
- 앱 로그는 `%LOCALAPPDATA%\DocuLens\logs\DocuLens.log`에 씁니다. 동작하지 않던 설정 항목(DB 암호화 등)은 화면에서 뺐습니다. 매일 파기를 꺼도 "지금 파기"는 동작합니다.

### 문서 · 처리

- `&` 뒤에 한글이 오는 HTML에서 변환이 멈추던 문제를 고쳤고, 변환기 하나가 실패해도 그 문서만 실패합니다.
- 다시 렌더해도 추출됨·검토됨 상태가 남습니다. 같은 경로에 다른 내용의 파일이 오면 새 문서로 처리합니다.
- Office 잠금 파일(`~$…`)·임시 파일은 문서로 등록하지 않습니다. 다른 프로그램이 쓰는 파일의 삭제는 실패로 알립니다.
- 구형 `.ppt`의 제목·본문, 구형 `.doc` 표의 빈 셀을 읽습니다.
- 이름만 바뀐 문서를 자동으로 다시 추출하지 않습니다. **다시 처리해도 손으로 고친 페이지 글자는 남습니다**("직접 고친 글자도 다시 읽기"를 켜야 바뀜). 강제 재처리("잔글씨 프로파일로 다시", "처음부터 다시"),
  검토함의 재추출, 양식 테스트는 먼저 묻습니다.
- 처리 작업을 재시도·재개하면 끝난 문서는 건너뜁니다. 엔진이 죽으면 남은 문서를 오류로 만들지 않고 작업을 멈춥니다. 잘린 응답 하나가 문서 전체 추출을 실패시키지 않습니다(그 쪽만 검토 대상).
- 날짜("14.10.2026")와 금액("1억 1천만 원", 숫자가 여럿인 칸)을 바르게 읽고, 모호하면 검토로 보냅니다. 개인정보 마스킹이 켜져 있으면 주민등록번호가 색인과 추출 미러에서도 가려집니다.
- 회전 보정이 문서 전체에 적용됩니다. '일반' 양식은 끌 수 없고, 양식을 지우거나 유형을 바꾸면 문서 쪽에 반영됩니다.

### 참고 자료 · 질문

- 후속 질문이 범위 밖의 이전 근거를 인용하지 않습니다. 워크스페이스를 바꾼 뒤 카드가 다른 DB에 저장되지 않습니다.
- 붙여 넣은 글 다듬기가 4,000자에서 잘리지 않고 모델 컨텍스트에 맞춰 처리되며, 잘렸으면 카드에 표시합니다.
- 최신판을 지우면 남은 판이 다시 검색됩니다. 용어집 확장이 복합어("공급가액")와 여러 낱말 동의어에 동작합니다.
- "중지"가 첫 글자 전에도, 다른 작업 뒤에서 기다리는 중에도 바로 듣습니다.

### 문서 작성

- 보완요청서 초안에서 초안 어시스턴트가 동작합니다. 목록 블록에 입력할 수 있습니다. 금액만 원화로 찍고 수량·시간은 입력한 대로 둡니다.
- 취소하거나 뒤늦게 끝난 초안 작업이 저장된 초안을 덮어쓰지 않습니다. "문서 작성 화면에서 열기"가 최신 초안을 엽니다.
- 내용·지시 글자 한도를 화면에 보이고, 넘치면 잘렸다고 알립니다. 등록 양식으로 저장할 때 빠지는 본문이 있으면 알립니다.

### 프로젝트

- 이미 등록된 파일을 프로젝트에 끌어다 놓으면 그 문서가 추가됩니다. 보완요청서에 필수 서류 누락이 들어갑니다.
- 추출 전 문서의 규칙은 "불일치"가 아니라 "판정 불가(추출 전)"입니다. 일부 규칙만 검사한 결과가 최근 검사를 대체하지 않습니다.
- "완료 처리"는 그날 바로 완료가 됩니다. 자동 분류는 프로젝트에 들지 않은 업무 문서만 제안합니다.
- 프로젝트 사본은 사용자의 파일을 덮어쓰지 않고(`_2`, `_3` …), 사용자가 고친 사본은 지우지 않습니다.

### 배포 · 고지

- 설치파일의 고지문·SBOM의 모델 항목이 현재 모델(Gemma 4 · EmbeddingGemma 2)입니다. 번들 엔진 팩에 llama.cpp의 MIT 라이선스 전문이 들어가고 LLVM OpenMP 런타임을 고지합니다(PKG-16).
- 게시 워크플로는 태그가 다른 커밋을 가리키는 Release에 올리지 않고, 버전 일치와 릴리스 노트 존재를 검사합니다. 액션은 커밋 해시로 고정했습니다.
- 설정 > 정보의 "고지 보기"가 설치된 파일을 엽니다.

## 3. 쓰던 방식과 달라지는 점

- **다시 처리(강제)** 가 손으로 고친 페이지 글자를 덮어쓰지 않습니다. 덮어쓰려면 처리 메뉴에서 "직접 고친 글자도 다시 읽기"를 켭니다.
- **표의 열 이름으로 `page`를 쓸 수 없습니다.** 그런 사용자 양식은 추출은 되지만, 다시 저장하려면 열 키를 바꿔야 합니다.
- 금액 칸에 숫자가 여럿이거나 날짜의 일·월 순서가 모호하면 값을 추측하지 않고 **검토함으로 보냅니다** — 검토 건수가 늘 수 있습니다.
- 유형의 마지막 양식을 지우면 그 유형이던 문서의 유형이 비워집니다.
- 종료일이 오늘인 프로젝트는 오늘 "완료"로 보입니다.
- 프로젝트 사본 폴더 이름은 영어 UI에서도 한국어 유형 이름을 씁니다(UI 언어에 따라 폴더가 갈리지 않도록).
- 개인정보 마스킹은 새로 색인하는 문서부터 색인에 적용됩니다. 이미 색인된 문서는 다시 색인해야 가려집니다(설정 > 참고 자료 > 다시 색인).
- 앱을 두 번 실행하면 두 번째는 뜨지 않고 열려 있는 창이 앞으로 나옵니다.
- 플래너 op는 63개 그대로이고, `answer`에 `mode`·`reply`, `summarize`에 `group_by`, 플랜에 `unmet`이 생겼습니다. 설정 카탈로그는 47 → 46개(`privacy.db_encryption` 제거).

## 4. 이번 판에서 하지 않은 것

- **PKG-1** — Release v0.1.0에 게시된 CUDA 재배포 자산과 앱 EULA 문제는 결정이 필요해 손대지 않았습니다(점검 목록 "결정이 필요한 것").
- **PLN-20** — 오래 걸리는 작업의 자동 실행은 사용자 결정으로 그대로 둡니다.
- **PKG-11(일부)** — 로그 위치는 고쳤지만, 앱을 제거할 때 `%LOCALAPPDATA%\DocuLens\`를 함께 지우는 처리는 NSIS 빌드에서 시험해야 해서 넣지 않았습니다.
- **PKG-14(일부)** — 액션 고정과 읽기 전용 기본 권한은 넣었고, 빌드 잡과 게시 잡의 분리는 하지 않았습니다.
- **KNO-14(일부)** — "중지"는 바로 응답하지만, 엔진은 그 요청의 첫 출력이 나올 때까지 계속 일합니다(그 사이 다음 질문은 기다림).
- **PRJ-4(일부)** — 구분 전환의 부작용(공용 참고 자료가 파기 대상이 되는 것)은 막았고, 문서 역할을 프로젝트별로 따로 두는 구조 변경은 하지 않았습니다.
- 규칙 해석 모드에서 "…하고 …" 두 요청 문장 일부(골든셋 ko-105)는 여전히 한 요청만 읽습니다(모델 경로는 읽음).

## 5. 확인하지 못한 것

이 판은 Linux 빌드 환경에서 만들고 시험했습니다. 아래는 코드와 단위 테스트로만 확인했고 **사용자 PC에서 확인이 필요**합니다(체크리스트 "0.8.0" 절).

- Windows 전용 코드: 단일 실행, 잠금 파일, 숨김/시스템 파일 건너뛰기, 사용 중인 파일 삭제 실패, 로그 폴더, "폴더 열기", 디스크 여유 공간.
- GPU: 자동 백엔드 선택(내장 그래픽 건너뛰기, Vulkan 로더 확인), CUDA 팩과 번들 팩의 우선순위.
- 실제 모델: 위 "측정"에 적은 문장 수만 실제 모델로 돌렸습니다(CPU에서 플랜 한 건에 수 분). 골든셋 전체의 실제 모델 정확도는 측정하지 않았습니다. 답변의 "일반 지식" 표시는 모델이 첫 줄에
  표시를 쓰는 것에 기대므로, 작은 모델(E2B)에서 표시가 빠지는지 확인이 필요합니다.
- 설치파일: 이 저장소의 Actions에서 빌드만 했고 설치·실행은 하지 않았습니다.
