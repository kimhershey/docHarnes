# DocuLens 1.0.0 (초안)

> **초안입니다.** 1.0.0 계획(`docs/plan/v1.0.0.md`)을 항목 단위로 진행하면서 끝난 것만 적습니다. 릴리스할 때 설치파일 표와 "확인한 것 / 확인하지 못한 것"을
> 확정합니다. 진행 상황과 다음 시작 지점은 계획 문서 0절에 있습니다.

v0.8.2 이후의 변경입니다. 0.8.2 작업 공간은 그대로 열립니다(데이터 구조 변경 없음 — 스키마 버전 12 그대로).

## 동작이 달라지는 점

업데이트하면 설정을 바꾸지 않아도 달라지는 것들입니다.

1. **어시스턴트가 고른 작업 목록은 기본으로 숨깁니다.** 질문 · 검색 · 요약 · 설명 · 비교 · 집계처럼 묻기만 하는 요청의 계획 카드와 결과 카드에서 단계 목록이 빠집니다.
   삭제 · 이동 · 설정 변경처럼 확인 카드가 뜨는 작업과 문서를 바꾸는 작업은 종전처럼 항상 단계를 보여 줍니다. 설정 > 일반의 "어시스턴트가 고른 작업 표시"로 켤 수 있고,
   "어시스턴트 작업 표시 켜줘"라고 말해도 됩니다.
2. **문서 작성은 고른 문서 안에서만 내용을 가져옵니다.** 종전에는 프로젝트 · 문서함 전체에서 비슷한 대목을 찾아 넣어, 인용 문서가 아닌 문서의 내용이 초안에 섞였습니다.
   "참고 자료에서 근거 더 찾기"는 기본 꺼짐이고, 켜면 참고 자료에서만 찾습니다(업무 문서 전체가 아님).
3. **"프로젝트에 넣기"가 현재 프로젝트를 미리 체크하지 않습니다.** 프로젝트를 여러 개 고를 수 있게 되면서, 미리 체크된 현재 프로젝트가 눈에 띄지 않은 채 남아 문서가 한
   프로젝트에 더 들어갈 수 있었습니다. 현재 프로젝트는 목록 맨 위에 "현재 프로젝트" 표시와 함께 나옵니다.
4. **쪽 그림이 지워진 문서를 처리하면 먼저 다시 렌더합니다.** 보존 정책으로 쪽 그림 캐시가 비워진 스캔 문서는 종전에 아무것도 읽지 않은 채 "처리됨"이 됐습니다.
   다시 렌더하지 못하면 사유와 함께 처리 오류로 표시합니다.
5. **어시스턴트에게 말로 한 "…을 설명해줘"는 문서에서 찾아 답하는 질문으로 처리됩니다.** 종전에는 따로 있던 '설명' 작업으로 갔습니다. 프로젝트를 말하면 그 프로젝트의 문서에서,
   "이 조항" · "이 문서"처럼 열린 문서를 가리키면 그 문서에서 답합니다. 뷰어에서 글을 선택해 누르는 "설명"과, 해석 방식을 "규칙"으로 둔 경우는 종전과 같습니다.

## 무엇이 달라졌나

### 프로젝트에 넣기 — 프로젝트 여러 개, 문서별 지정

- 프로젝트 목록이 체크 목록입니다(검색, 전체 선택 / 전체 해제). 여러 개를 체크하면 고른 문서가 체크한 프로젝트 전부에 들어갑니다.
- 문서를 둘 이상 골랐으면 **"문서별로 지정"** 을 쓸 수 있습니다. 행은 문서, 열은 프로젝트인 표에서 칸마다 체크합니다.
  - 열 머리의 체크는 보이는 문서 전체에 적용됩니다. 검색하거나 "프로젝트를 지정하지 않은 문서만"으로 좁힌 뒤 행을 골라(Shift로 범위) 한꺼번에 추가 · 빼기 · 종류 바꾸기를 할 수 있습니다.
  - 종류(업무 문서 / 참고 자료)는 문서마다 정합니다. 종류를 바꾼 문서는 이미 든 프로젝트에서도 그 종류로 옮겨집니다.
  - 이미 든 프로젝트의 칸은 체크된 채로 시작하고, 체크를 풀면 그 프로젝트에서 뺍니다. 빼는 문서가 있으면 적용 전에 대상을 따로 보여 주고 한 번 더 확인합니다(문서는 지워지지 않고 문서함에 남습니다).
  - 표 아래에 프로젝트별 넣기 · 빼기 건수와 지정하지 않은 문서 수가 계속 보입니다.
- 적용은 한 번에 되고, 알림의 **"되돌리기"** 로 방금 한 배정 전체를 되돌립니다(프로젝트 하나만 골랐을 때의 알림은 종전처럼 "열기").
- **자동 분류 제안**: 제안된 프로젝트를 체크해 주고, 2순위 후보도 신뢰도가 임계값 이상이면 함께 체크합니다. 문서마다 제안이 다르면 "문서별로 지정"으로 바뀌어 문서별로 채웁니다.
  나머지 후보는 문서 이름 아래 "후보 … %" 로 보이고 누르면 체크됩니다.
- 임계값은 설정 > 처리의 **"프로젝트 분류(2순위 추천 임계값)"**(기본 60 %)이고 "2순위 추천 임계값 70%로 바꿔줘"처럼 말로 바꿀 수 있습니다.
- 한 문서가 여러 프로젝트의 업무 문서가 되면 둘째 프로젝트부터는 종전처럼 그 프로젝트 폴더에 추적 사본이 생깁니다.

### 이미지 내 글자 추출 (설정 > 처리, 기본 꺼짐)

글자 층이 있는 문서(디지털 PDF, PPT · Word · 한글 변환본) 안의 그림 — 구성도, 화면 캡처, 그림으로 넣은 표 — 에 든 글자는 종전에 어디에도 들어가지 않았습니다.
스위치를 켜면 처리할 때 그림만 잘라 읽어(쪽 전체를 다시 OCR하지 않으므로 본문 글자는 그대로입니다) 쪽의 글과 글자 층에 넣습니다.

- 뷰어에서 그림 위의 글자를 드래그해 선택하고 고칠 수 있고, 검색 · 질문 · 추출에도 쓰입니다. "[그림] …" 같은 표식은 붙이지 않습니다.
- 아이콘 · 로고처럼 작은 그림, 선 · 띠 모양, 글자 층의 글이 위에 겹친 그림(글자 층이 있는 스캔, 슬라이드 배경)은 읽지 않습니다. 같은 그림이 여러 쪽에 나오면 한 번만 읽습니다.
- 그림마다 모델을 한 번 부릅니다. 쪽당 6개, 문서당 40회까지입니다.
- 켠 뒤에 처리하는 문서부터 적용됩니다. 이미 처리한 문서는 다시 처리하면 반영되고, 한 번 읽은 그림은 다시 읽지 않습니다(강제 다시 처리 때만 새로 읽습니다).
- "이미지 내 글자 추출 켜줘"처럼 말로도 켜고 끌 수 있습니다.
- 스캔 문서 · 사진은 종전처럼 쪽 전체를 OCR합니다.

### PPTX가 PowerPoint와 다르게 보이던 문제 (일부)

- **표**: 셀 바탕색, 테두리, 세로 정렬, 행 높이와 표 스타일을 읽습니다. PowerPoint 기본 표(파란 머리글에 흰 굵은 글자, 줄무늬 행)가 종전에는 회색 선의 민무늬 표로 나왔습니다.
  파일에 정의가 든 표 스타일과 기본 스타일("보통 스타일 2 - 강조 1")을 지원하고, 그 밖의 내장 스타일은 종전처럼 나옵니다.
- **제목 · 본문이 빠지던 슬라이드**: 레이아웃이 제목 자리만 되풀이하고 위치는 마스터에 있는 서식(표준 서식에서 흔함)에서 제목과 본문이 슬라이드에서 통째로 빠졌습니다.
  위치 · 글자 크기 · 색 · 정렬을 슬라이드 → 레이아웃 → 마스터 순으로 이어 받도록 고쳤습니다.
- **배경**: 그림 배경, 그라데이션 배경(선형 · 가운데에서 퍼지는 것), 바둑판으로 깐 그림, 테마의 배경 채움을 그립니다. 종전에는 단색만 나오고 나머지는 흰 바탕이었습니다.
- **마스터 · 레이아웃의 로고와 장식**: 슬라이드 마스터와 레이아웃에 놓인 로고 · 색 띠 · 고정 글이 모든 슬라이드에 나옵니다. "배경 그래픽 숨기기"를 켠 슬라이드에서는 나오지 않습니다.
  검색과 질문에 쓰는 본문(읽기 순서 글)에는 넣지 않습니다. 다만 화면에 보이는 글이므로 쪽 글자 층에는 들어갑니다.
- **그린 도형의 색**: PowerPoint에서 그린 상자 · 화살표는 색이 도형 스타일에만 적혀 있어서 채움 없이 검은 글자로 나왔습니다. 테마 강조색 채움과 테두리, 흰 글자로 나옵니다.
  그라데이션 채움과 그림 채움도 그립니다.
- **도형의 모양**: 화살표 · 갈매기(단계 표시) · 마름모 · 삼각형 · 육각형 · 평행사변형 · 사다리꼴과 자유형(직접 그린 도형)이 사각형이 아니라 제 모양으로 나옵니다.
  뒤집은 도형 안의 글자가 거울상으로 나오던 것도 고쳤습니다. 그 밖의 기본 도형(별 · 말풍선 · 굽은 화살표 등)은 아직 상자로 나옵니다.
- **차트**: "차트"라고 적힌 점선 틀만 나오던 것을, 파일에 저장된 값으로 다시 그립니다. 세로 · 가로 막대(묶음 / 누적 / 100 % 누적), 선, 영역, 원형, 도넛, 막대 + 선 혼합을 지원합니다.
  제목 · 축 제목 · 눈금 · 범례 · 값 라벨은 그림이 아니라 글자로 들어가므로 뷰어에서 드래그해 선택할 수 있고 검색과 질문에 잡힙니다.
  분산형 · 방사형처럼 그리지 못하는 종류는 데이터 표로 대신 보여 줍니다. 모양은 PowerPoint와 똑같지 않습니다(3D, 보조 축, 추세선, 세부 서식은 반영하지 않음). Word · Excel 문서 안의 차트는 아직 종전과 같습니다.

### 원본 고치기 — HWPX · DOCX · PPTX 원본을 서식 그대로 고치기

뷰어에서 고친 글은 지금까지 쪽 글(검색 · 질문에 쓰는 글)만 바꿨고 원본 파일은 그대로였습니다. 이제 원본 파일 안의 글을 바꾸고, 문단과 표의 행을 더하거나 빼서 새 파일로 저장할 수 있습니다.

- **뷰어의 "원본 고치기"**(HWPX · DOCX · PPTX 문서에만 나옵니다): 찾을 글과 바꿀 글을 여러 줄 적고 "미리 보기"를 누르면 문단마다 바꾸기 전 / 후를 보여 줍니다. 본 뒤에만 저장할 수 있습니다.
  뷰어에서 글을 드래그해 둔 채로 열면 그 글이 찾을 글에 들어갑니다.
- **문단과 표의 행**: 줄마다 작업을 고릅니다 — 글 바꾸기 / 문단 추가(앞 · 뒤) / 문단 삭제 / 표 행 추가(위 · 아래) / 표 행 삭제. 자리는 "그 문단(행)에 들어 있는 글"로 가리킵니다.
  새 문단은 기준 문단의 문단 모양과 글자 모양을, 새 행은 기준 행의 칸 모양을 본뜹니다(새 행의 칸은 ` | `로 나눠 적습니다). 같은 글이 여러 곳에 있으면 몇 번째인지 물어보고, 그 전에는 저장되지 않습니다.
  한글(HWPX) 표는 행 번호와 행 수를 다시 매기고, PowerPoint 표는 틀 높이를 행 높이만큼 고칩니다.
- **원본은 건드리지 않습니다.** 고친 파일은 원본 옆에 `이름 (수정).확장자`로 저장되고(이미 있으면 `(수정 2)` …), 문서함에 새 문서로 올라가 **최신 판**이 됩니다. 원본은 "원본" 판으로 남습니다.
  제목 · 문서 유형 · 태그 · 프로젝트와 참고 자료 묶음 소속은 원본에서 이어받습니다.
- **서식은 그대로입니다.** 파일 안에서 글이 든 부분의 글자만 바꾸고 나머지(글꼴 · 문단 모양 · 표 · 그림 · 머리글 · 스타일)는 원본의 바이트 그대로 옮깁니다. 바꾼 글은 그 자리에 있던 글의
  글씨체 · 크기 · 색을 따릅니다. 한 낱말이 서식이 다른 조각으로 나뉘어 저장돼 있어도 찾습니다.
- **어시스턴트로도 됩니다.** 문서를 열거나 하나 고른 뒤 "원본에서 '11월 30일'을 '12월 31일'로 바꿔줘"라고 하면, 원본 파일에서 몇 곳이 바뀌는지 확인 카드로 먼저 보여 주고 실행하면 새 판으로 저장합니다.
  "원본" · "새 판으로"를 말하지 않으면 종전처럼 쪽 글만 바꿉니다. 어느 문서인지 말하지 않으면 선택한 문서, 없으면 열어 둔 문서에 합니다.
- **되지 않는 것**: 한 문단을 넘는 글(줄바꿈이 든 글), 그림 바꾸기, 새 표 넣기, 엑셀(XLSX) 셀, 옛 형식(HWP · DOC · PPT — 한컴오피스 / 오피스에서 새 형식으로 저장한 뒤 가능), PDF.
  변경 내용 추적이 들어 있는 DOCX와 전자서명이 된 문서는 고치지 않고 이유를 알려 줍니다.
- **손대지 않는 문단과 행**(이유를 알려 주고 그 줄만 "확인 필요"로 남습니다): 글 말고 다른 것이 든 문단의 삭제(구역 나눔 · 표 · 그림 · 필드 · 각주 · 책갈피의 한쪽), 표 바로 뒤의 문단, 칸 · 글상자 · 본문에 하나뿐인 문단,
  두 벌로 저장된 글상자 안의 문단, 세로로 병합된 칸이 있는 표의 행, 표에 하나 남은 행. 어시스턴트 명령은 아직 글 바꾸기만 합니다(문단 · 행은 뷰어의 대화상자에서).

### 어시스턴트 — 비슷한 동작 줄이기

같은 일을 하는 동작이 여러 개 있으면 작은 모델이 그 사이에서 잘못 고릅니다(0.8.x의 실제 모델 측정에서 확인). 모델에게 보여 주는 동작을 63개에서 57개로 줄였습니다.

- **설정을 바꾸는 길은 하나입니다.** 테마 · 언어 · 프로파일 · 모델 · inbox 감시를 바꾸는 전용 동작 5개를 모델의 목록에서 빼고, 어느 경로로 해석하든 '설정 변경' 한 가지로 처리합니다.

- **"설명해줘"는 질문입니다.** '설명' 동작을 모델의 목록에서 뺐습니다(위 "동작이 달라지는 점" 5). 모델이 그런 질문을 "문서를 찾지 않는 답변"으로 적더라도, 문장이 프로젝트를 말하거나 열린 문서를
  가리키면 문서에서 찾아 답하도록 바로잡습니다.
- 실제 모델(Gemma 4 E4B, CPU)로 잰 결과는 아래 "확인한 것"과 `eval/results/planner-real-model/README.md`에 있습니다.
- 결과 카드에서 실패한 단계는 사유 코드 대신 문장으로 보여 줍니다(예: "바꿀 곳을 찾지 못했습니다. 문서에 적힌 그대로 입력했는지 확인하세요.").

### 문서 고르는 화면

- 문서 작성의 원본 고르기, 프로젝트의 문서 추가, 양식 등록에 **전체 선택 / 전체 해제** 와 선택 개수가 생겼습니다. 보이는 행에만 적용되므로 검색이나 프로젝트로 좁혀 여러 번 나눠 고를 수 있습니다.
- 같은 화면들에서 **프로젝트로 좁히기** 가 됩니다(그 프로젝트의 업무 문서와 참고 자료).
- 문서함 카드와 목록에 **소속 프로젝트 배지** 가 붙습니다(최대 2개 + "+n", 참고 자료로 든 프로젝트는 따로 표시).

### 그 밖의 수정

- 해석 방식을 "규칙"으로 둔 경우: 이름을 붙이지 않은 "임계값 70%로 바꿔줘"는 어느 임계값인지 묻습니다(검토 임계값 / 2순위 추천 임계값 — 종전에는 묻지 않고 검토 임계값을 바꿨습니다).
  "신뢰도 기준 0.9로 설정"처럼 소수로 쓴 값이 0으로 읽히던 문제를 고쳤습니다.
- 비전 프로젝터(mmproj) 파일 없이 로드된 모델로 그림을 읽으려 하면, 엔진의 영어 오류 대신 "모델에 비전 프로젝터 파일이 없어 …"라고 안내하고 일괄 처리를 그 자리에서 멈춥니다(남은 문서는 그대로 둡니다).

## 확인하지 못한 것

- Windows 설치 · 실행, 한컴오피스 · PowerPoint 원본과의 대조(사용자 PC 체크리스트).

  HWPX에서 글자 수가 달라진 문단의 줄바꿈이 다시 잡히는지, 행을 더한 HWPX 표의 높이와 PowerPoint 표의 틀을 프로그램이 다시 맞추는지는 사용자 PC 체크리스트의 "원본 고치기" 항목으로 확인해야 합니다.

- 실제 모델 확인은 CPU에서 샘플 문서 하나로 했습니다. 작은 글자 · 빽빽한 그림 · 사진, 여러 쪽에 반복되는 그림, GPU, E2B 모델, PPTX · DOCX · HWP 변환본은 재지 않았습니다.

## 알려진 제한

- **그림 안 글자의 선택 상자가 일부 어긋납니다.** 그림 글자의 위치는 그림을 위에서 아래로 줄 단위로 나눠 추정합니다. 한 줄에 글이 하나만 있는 부분(제목, 출처, 표의 행)은 맞지만,
  가로로 나란한 라벨(구성도의 상자 여러 개가 한 줄)과 글 옆에 표가 나란한 부분에서는 상자가 글자와 어긋납니다. 위 실제 모델 확인에서 확인한 것입니다.
  검색 · 질문 · 추출은 쪽 글을 쓰므로 영향이 없고, 뷰어에서 그림 위를 드래그해 고를 때 그 부분이 부정확합니다. 그림을 블록 단위로 나눠 위치를 잡는 보강은 **1.1.0** 으로 넘겼습니다.
