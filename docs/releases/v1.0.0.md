# DocuLens 1.0.0 (초안)

> **초안입니다.** 1.0.0 계획(`docs/plan/v1.0.0.md`)을 항목 단위로 진행하면서 끝난 것만 적습니다. 릴리스할 때 설치파일 표와 "확인한 것 / 확인하지 못한 것"을
> 확정합니다. 진행 상황과 다음 시작 지점은 계획 문서 0절에 있습니다.

v0.8.2 이후의 변경입니다. 0.8.2 작업 공간은 그대로 열립니다(데이터 구조 변경 없음 — 스키마 버전 12 그대로).

## 동작이 달라지는 점

업데이트하면 설정을 바꾸지 않아도 달라지는 것들입니다.

1. **어시스턴트가 고른 작업 목록은 기본으로 숨깁니다.** 질문 · 검색 · 요약 · 설명 · 비교 · 집계처럼 묻기만 하는 요청의 계획 카드와 결과 카드에서 단계 목록이 빠집니다.
   삭제 · 이동 · 설정 변경처럼 확인 카드가 뜨는 작업과 문서를 바꾸는 작업은 종전처럼 항상 단계를 보여 줍니다. 설정 > 일반의 "어시스턴트가 고른 작업 표시"로 켤 수 있고,
   "어시스턴트 작업 표시 켜줘"라고 말해도 됩니다.
2. **문서 작성은 고른 문서 안에서만 내용을 가져옵니다.** 종전에는 프로젝트 · 문서함 전체에서 비슷한 대목을 찾아 넣어, 인용 문서가 아닌 문서의 내용이 초안에 섞였습니다.
   "참고 자료에서 근거 더 찾기"는 기본 꺼짐이고, 켜면 참고 자료에서만 찾습니다(업무 문서 전체가 아님).
3. **"프로젝트에 넣기"가 현재 프로젝트를 미리 체크하지 않습니다.** 프로젝트를 여러 개 고를 수 있게 되면서, 미리 체크된 현재 프로젝트가 눈에 띄지 않은 채 남아 문서가 한
   프로젝트에 더 들어갈 수 있었습니다. 현재 프로젝트는 목록 맨 위에 "현재 프로젝트" 표시와 함께 나옵니다.
4. **쪽 그림이 지워진 문서를 처리하면 먼저 다시 렌더합니다.** 보존 정책으로 쪽 그림 캐시가 비워진 스캔 문서는 종전에 아무것도 읽지 않은 채 "처리됨"이 됐습니다.
   다시 렌더하지 못하면 사유와 함께 처리 오류로 표시합니다.

## 무엇이 달라졌나

### 프로젝트에 넣기 — 프로젝트 여러 개, 문서별 지정

- 프로젝트 목록이 체크 목록입니다(검색, 전체 선택 / 전체 해제). 여러 개를 체크하면 고른 문서가 체크한 프로젝트 전부에 들어갑니다.
- 문서를 둘 이상 골랐으면 **"문서별로 지정"** 을 쓸 수 있습니다. 행은 문서, 열은 프로젝트인 표에서 칸마다 체크합니다.
  - 열 머리의 체크는 보이는 문서 전체에 적용됩니다. 검색하거나 "프로젝트를 지정하지 않은 문서만"으로 좁힌 뒤 행을 골라(Shift로 범위) 한꺼번에 추가 · 빼기 · 종류 바꾸기를 할 수 있습니다.
  - 종류(업무 문서 / 참고 자료)는 문서마다 정합니다. 종류를 바꾼 문서는 이미 든 프로젝트에서도 그 종류로 옮겨집니다.
  - 이미 든 프로젝트의 칸은 체크된 채로 시작하고, 체크를 풀면 그 프로젝트에서 뺍니다. 빼는 문서가 있으면 적용 전에 대상을 따로 보여 주고 한 번 더 확인합니다(문서는 지워지지 않고 문서함에 남습니다).
  - 표 아래에 프로젝트별 넣기 · 빼기 건수와 지정하지 않은 문서 수가 계속 보입니다.
- 적용은 한 번에 되고, 알림의 **"되돌리기"** 로 방금 한 배정 전체를 되돌립니다(프로젝트 하나만 골랐을 때의 알림은 종전처럼 "열기").
- **자동 분류 제안**: 제안된 프로젝트를 체크해 주고, 2순위 후보도 신뢰도가 임계값 이상이면 함께 체크합니다. 문서마다 제안이 다르면 "문서별로 지정"으로 바뀌어 문서별로 채웁니다.
  나머지 후보는 문서 이름 아래 "후보 … %" 로 보이고 누르면 체크됩니다.
- 임계값은 설정 > 처리의 **"프로젝트 분류(2순위 추천 임계값)"**(기본 60 %)이고 "2순위 추천 임계값 70%로 바꿔줘"처럼 말로 바꿀 수 있습니다.
- 한 문서가 여러 프로젝트의 업무 문서가 되면 둘째 프로젝트부터는 종전처럼 그 프로젝트 폴더에 추적 사본이 생깁니다.

### 이미지 내 글자 추출 (설정 > 처리, 기본 꺼짐)

글자 층이 있는 문서(디지털 PDF, PPT · Word · 한글 변환본) 안의 그림 — 구성도, 화면 캡처, 그림으로 넣은 표 — 에 든 글자는 종전에 어디에도 들어가지 않았습니다.
스위치를 켜면 처리할 때 그림만 잘라 읽어(쪽 전체를 다시 OCR하지 않으므로 본문 글자는 그대로입니다) 쪽의 글과 글자 층에 넣습니다.

- 뷰어에서 그림 위의 글자를 드래그해 선택하고 고칠 수 있고, 검색 · 질문 · 추출에도 쓰입니다. "[그림] …" 같은 표식은 붙이지 않습니다.
- 아이콘 · 로고처럼 작은 그림, 선 · 띠 모양, 글자 층의 글이 위에 겹친 그림(글자 층이 있는 스캔, 슬라이드 배경)은 읽지 않습니다. 같은 그림이 여러 쪽에 나오면 한 번만 읽습니다.
- 그림마다 모델을 한 번 부릅니다. 쪽당 6개, 문서당 40회까지입니다.
- 켠 뒤에 처리하는 문서부터 적용됩니다. 이미 처리한 문서는 다시 처리하면 반영되고, 한 번 읽은 그림은 다시 읽지 않습니다(강제 다시 처리 때만 새로 읽습니다).
- "이미지 내 글자 추출 켜줘"처럼 말로도 켜고 끌 수 있습니다.
- 스캔 문서 · 사진은 종전처럼 쪽 전체를 OCR합니다.

### 문서 고르는 화면

- 문서 작성의 원본 고르기, 프로젝트의 문서 추가, 양식 등록에 **전체 선택 / 전체 해제** 와 선택 개수가 생겼습니다. 보이는 행에만 적용되므로 검색이나 프로젝트로 좁혀 여러 번 나눠 고를 수 있습니다.
- 같은 화면들에서 **프로젝트로 좁히기** 가 됩니다(그 프로젝트의 업무 문서와 참고 자료).
- 문서함 카드와 목록에 **소속 프로젝트 배지** 가 붙습니다(최대 2개 + "+n", 참고 자료로 든 프로젝트는 따로 표시).

### 그 밖의 수정

- 비전 프로젝터(mmproj) 파일 없이 로드된 모델로 그림을 읽으려 하면, 엔진의 영어 오류 대신 "모델에 비전 프로젝터 파일이 없어 …"라고 안내하고 일괄 처리를 그 자리에서 멈춥니다(남은 문서는 그대로 둡니다).

## 확인한 것

- 단위 · 통합 테스트(Rust 코어, 웹), 브라우저 테스트(모의 백엔드), clippy, CI.
- "문서별로 지정" 표: 문서 200개 × 프로젝트 3개에서 표 열기 0.3초, 칸 · 열 체크 약 25 ms(모의 백엔드, 개발용 PC). UI 배율 150 %에서 표가 창 안에 있고 자기 상자 안에서만 스크롤되는지.
- 이미지 내 글자 추출을 **실제 모델**(Gemma 4 E4B Q4_K_M + 비전 프로젝터, CPU)로 돌렸습니다. 본문 두 문단 사이에 구성도와 표가 든 그림 하나를 넣은 PDF 한 쪽에서:

  | 설정 | 그림 속 문자열 24개 중 쪽 글에 들어온 것 | 본문 | 걸린 시간 |
  |---|---|---|---|
  | 꺼짐(기본) | 0 | 그대로 | 298초 |
  | 켜짐 | 24 ("SMS·메일"은 "SMS메일"로 읽힘) | 그대로 | 398초 |

  그림 글은 위 문단과 아래 문단 사이에 들어갔고, 그림은 그림 영역만 잘라 한 번 읽었습니다.

## 확인하지 못한 것

- Windows 설치 · 실행, 한컴오피스 · PowerPoint 원본과의 대조(사용자 PC 체크리스트).
- 실제 모델 확인은 CPU에서 샘플 문서 하나로 했습니다. 작은 글자 · 빽빽한 그림 · 사진, 여러 쪽에 반복되는 그림, GPU, E2B 모델, PPTX · DOCX · HWP 변환본은 재지 않았습니다.

## 알려진 제한

- **그림 안 글자의 선택 상자가 일부 어긋납니다.** 그림 글자의 위치는 그림을 위에서 아래로 줄 단위로 나눠 추정합니다. 한 줄에 글이 하나만 있는 부분(제목, 출처, 표의 행)은 맞지만,
  가로로 나란한 라벨(구성도의 상자 여러 개가 한 줄)과 글 옆에 표가 나란한 부분에서는 상자가 글자와 어긋납니다. 위 실제 모델 확인에서 확인한 것입니다.
  검색 · 질문 · 추출은 쪽 글을 쓰므로 영향이 없고, 뷰어에서 그림 위를 드래그해 고를 때 그 부분이 부정확합니다. 그림을 블록 단위로 나눠 위치를 잡는 보강은 **1.1.0** 으로 넘겼습니다.
