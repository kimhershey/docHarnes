v1.0.4 이후의 수정입니다. 어시스턴트가 문장을 읽는 방식 네 가지와 화면의 표시 두 가지를 고쳤습니다.
설치·실행 방법은 [docs/RUN-GUIDE.md](https://github.com/kimhershey/docHarnes/blob/v1.0.5/docs/RUN-GUIDE.md), 사용자 PC에서 확인할 항목은
[docs/user-pc-checklist.md](https://github.com/kimhershey/docHarnes/blob/v1.0.5/docs/user-pc-checklist.md)의 "1.0.5" 절을 보세요. **Lite 설치파일만** 배포합니다.

1.0.4 작업 공간은 그대로 열립니다(데이터 구조 변경 없음, 다시 색인할 필요 없음).

## 무엇이 달라졌나

### "알려줘"는 검색이 아니라 답변

- "BB 알려줘", "BB에 대해 알려줘"는 문서에서 근거를 찾아 답합니다. 검색 결과 목록으로 나오지 않습니다.
- 장소를 말하면("AA 프로젝트의 BB에 대해 알려줘", "이 문서에서 BB에 대해 알려줘") "설명해줘"와 같이 그 범위에서 BB에 관한 내용을 모아 요약합니다.
- "찾아줘", "검색", "목록", "어디 있어"처럼 찾기를 말한 문장은 검색입니다. 모델이 "찾아줘"를 "그 이름의 문서 열기"로 잘못 읽던 경우도 검색으로 바로잡습니다.

### 두 가지로 읽히는 문장은 먼저 묻습니다

바로 실행하지 않고 카드에 해석 선택지를 보여 줍니다. 고르면 모델을 다시 부르지 않고 바로 진행합니다.

| 경우 | 예 | 선택지 |
|---|---|---|
| 말한 이름이 프로젝트 이름이기도 함 | "AAA에 대해 요약해줘" | AAA 프로젝트의 문서 전체 / 모든 문서에서 AAA에 관한 내용 / AAA 프로젝트의 문서에서 AAA에 관한 내용 |
| 말한 이름이 문서 유형 이름이기도 함 | "견적서에 대해 요약해줘" | 유형이 견적서인 문서 / 문서에서 '견적서'에 관한 내용 |
| 유형으로 분류된 문서와 제목에만 그 이름이 든 문서가 함께 있음 | "요구사항 정의서 요약해줘" | 분류된 문서 N건 / 이름이 있는 문서 M건 / 둘 다 |

"AAA 프로젝트 요약해줘"처럼 문장이 한쪽을 분명히 말하면 묻지 않습니다.

### 문서 유형 조건

- 질문·검색·설명에서는 유형을 조건으로 쓰지 않습니다. "'위약금' 들어간 계약서 찾아줘"의 "계약서"는 걸러낼 조건이 아니라 찾을 말입니다. 분류되지 않은 문서가 빠지지 않습니다.
- 요약·집계·내보내기와 문서를 바꾸는 명령에서는 종전대로 조건입니다. 다만 그 유형으로 분류된 문서뿐 아니라 제목이나 파일 이름에 유형 이름이 든 문서도 대상입니다.

### 문장이 말하지 않은 조건은 범위에 넣지 않습니다

"AAA 프로젝트의 참고자료 요약해줘"가 "참고 자료가 없습니다"로 실패하던 문제입니다. 모델이 프로젝트 이름을 태그 조건으로 쓰거나, 말하지 않은 상태 조건을 넣거나, 요약 문장에 "참고 자료에 추가" 단계를 붙이고 있었습니다.

- 읽기만 하는 요청(질문·검색·요약·집계·내보내기)에서는 문장에 없는 태그·상태·검토 상태·신뢰도·거래처·키워드·기간 조건을 뺍니다. 뺀 것은 카드에 알립니다.
- 넣기·빼기·옮기기를 말하지 않은 문장에 붙은 "참고 자료에 추가", "프로젝트에 넣기" 단계는 뺍니다.
- 범위에 문서가 없을 때의 안내가 실제 원인을 말합니다. 다른 조건 때문에 0건인데 "참고 자료가 없습니다"라고 하지 않습니다.

### 근거와 검색 결과의 쪽 표시

- 대목 하나가 여러 쪽에 걸칠 때 첫 쪽이 아니라 **찾은 말이 있는 쪽**을 표시하고 그 쪽으로 이동합니다. 여러 쪽 대목은 "p.4 (3–5쪽 대목)"처럼 범위를 함께 적습니다.
- 요약의 출처는 요약이 인용한 대목만 남기고, 번호를 인용한 순서대로 1부터 매깁니다. 전에는 문서 하나를 요약하면 모든 대목이 순번대로 나열됐습니다.
- 같은 문서 안에서 출처를 눌러도 해당 대목이 강조됩니다.
- 변환 문서(HWPX·DOCX 등) 중 글이 1쪽에만 저장된 것은 쪽 번호를 표시하지 않습니다(전에는 모든 출처가 p.1).

### 프로젝트 문서 수

프로젝트 카드, 목록, "프로젝트에 넣기" 창, 어시스턴트 결과의 문서 수가 업무 문서와 참고 자료를 합친 수입니다. 참고 자료만 넣은 프로젝트가 "문서 0건"으로 보이던 문제입니다. 프로젝트 상세 화면의 "업무 N · 참고 M"은 그대로입니다.

## 동작이 달라지는 점

- 프로젝트 이름이나 유형 이름과 겹치는 말로 요약·질문하면 선택지 카드가 한 번 뜹니다. 전에는 묻지 않고 한쪽으로 처리했습니다.
- "계약서 삭제해줘"처럼 유형을 말한 명령의 대상에 제목에 그 이름이 든 문서도 들어갑니다. 실행 전 확인 카드의 건수와 목록을 확인하세요.
- "AA 프로젝트의 BB에 대해 알려줘"는 답변이 아니라 주제 요약이라 CPU에서는 답변보다 오래 걸립니다.
- 1.0.4 이하에서 저장된 답변의 여러 쪽 출처는 "p.3-5" 대신 "p.3 (3–5쪽 대목)"으로 보입니다(가리키는 쪽은 같음).

## 확인한 것

- Rust 테스트 · clippy · 형식 검사, 웹 타입 검사 · 단위 테스트 374 · 브라우저(모의 백엔드) E2E 147, 플래너 골든셋 214문장 중 205(95.8 %, 틀린 9건은 1.0.4와 같은 문장).
- 실제 모델(Gemma 4 E4B Q4_K_M, CPU): "프로젝트 + 참고자료" 8문장이 고치기 전 3/8에서 8/8로, "알려줘" · 유형 조건 · 선택지 11문장 11/11. 잰 것은 문장 해석(계획)까지입니다.

## 확인하지 못한 것

- 실제 Windows 설치본에서의 동작, 사용자 문서(청크 크기 1,200)에서 쪽 표시가 맞는지. 체크리스트 "1.0.5" 절에 적었습니다.
- 유형 겹침 선택지는 셸의 계획 단계에서 DB를 보고 만듭니다. 코어 테스트와 모의 백엔드로 확인했고 실제 데스크톱 창에서는 돌려 보지 못했습니다.

## 알려진 제한

- 쪽은 "질문의 말이 처음 강조된 곳"의 쪽입니다. 모델이 실제로 인용한 문장이 같은 대목의 다른 쪽에 있을 수 있습니다.
- 문장에 없는 조건을 빼는 것은 읽기만 하는 요청에만 적용합니다. 삭제·이동 같은 명령에 모델이 엉뚱한 조건을 넣으면 "대상 문서 없음"으로 끝납니다(범위를 넓히지 않습니다).
- 유형 이름의 짧은 다른 말(계약, 견적, 검수, 요구사항)만 주제로 말해도 유형/말 선택지가 뜹니다.
