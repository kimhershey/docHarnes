# DocuLens 1.0.6

v1.0.5 이후의 수정입니다. 근거 설정의 상한을 풀었고, "다듬어줘 / 수정해줘"가 문서 작성으로 가지 않게 했습니다.
설치·실행 방법은 [docs/RUN-GUIDE.md](https://github.com/kimhershey/docHarnes/blob/v1.0.6/docs/RUN-GUIDE.md), 사용자 PC에서 확인할 항목은
[docs/user-pc-checklist.md](https://github.com/kimhershey/docHarnes/blob/v1.0.6/docs/user-pc-checklist.md)의 "1.0.6" 절을 보세요. **Lite 설치파일만** 배포합니다.

1.0.5 작업 공간은 그대로 열립니다(데이터 구조 변경 없음, 다시 색인할 필요 없음).

## 무엇이 달라졌나

### 근거 설정의 제한을 풀었습니다

| 설정 | 1.0.5 | 1.0.6 |
|---|---|---|
| 근거 토큰 예산 | 1,000 ~ 24,000 | 1,000 ~ 262,144 |
| 근거 청크 수 | 설정 화면 1 ~ 20 (어시스턴트로는 32) | 1 ~ 200 |
| 청크 크기 | 120 ~ 2,000 | 그대로 |

- **모델을 예산에 맞는 크기로 로드합니다.** 전에는 예산을 24,000으로 잡아도 "균형" 프로필은 컨텍스트 16,384로 로드해서 근거가 약 10,800토큰까지만 들어갔습니다. 이제 예산과 답변 몫이 다 들어가는 컨텍스트로 로드합니다(모델이 지원하는 최대까지). E4B 기준 예산 24,000 → 컨텍스트 30,720, 60,000 → 75,776, 그 이상은 131,072.
- **예산을 기본값(6,000) 이하로 두면 종전과 똑같이 로드합니다.**
- **답변 길이의 "기본의 4배까지" 상한이 없습니다.** 답변은 예산의 1/5, 요약은 1/4까지이고 모델 컨텍스트의 1/3을 넘지 않습니다.
- **실패하면 무엇을 할지 말합니다.** 로드가 실패하거나 요청이 너무 커서 거절되면 "근거 토큰 예산을 줄이세요"라고 안내합니다. 큰 값으로부터 미리 막아 주지 않습니다.
- **청크 크기 2,000은 그대로입니다.** 임베딩 모델이 한 번에 읽는 길이(2,048토큰)의 한계라서 더 올리면 조각의 뒷부분이 검색에 잡히지 않습니다. 설정 설명에 적었습니다.
- 설정 화면의 근거 토큰 예산 아래에 지금 로드된 모델의 컨텍스트를 표시합니다.

### "다듬어줘 / 수정해줘"는 문서 작성이 아닙니다

- 글을 다듬거나 고쳐 달라는 문장은 대화창에서 글로 답합니다. 문서 작성 화면으로 가지 않고, 문서의 글을 바꾸지도 않습니다.
- 다듬을 글은 문장과 함께 보낸 글, 없으면 바로 앞 답변(전체)입니다. 둘 다 없으면 어떤 글인지 묻습니다.
- 문서는 문장이 새 문서나 문서를 말할 때만 씁니다: "다듬어서 새 문서로 만들어줘", "이 내용으로 보고서 작성해줘".
- 그대로인 것: 문서 작성 화면에서 초안을 열어 둔 상태의 "3절 다시 써줘", 따옴표로 찾을 글과 바꿀 글을 말한 "'갑'을 '을'로 수정해줘", 설정·필드 값·태그 등 앱의 것을 말한 수정.

## 동작이 달라지는 점

- **근거 토큰 예산을 6,000보다 크게 둔 설치본은 업데이트 뒤 엔진이 시작될 때 모델을 더 큰 컨텍스트로 로드합니다.** 메모리(VRAM / RAM)를 더 쓰고, 근거가 많을수록 답이 나오기까지 오래 걸립니다. 느려지면 예산을 줄이세요.
- 예산을 바꾼 것은 엔진을 다시 시작해야 적용됩니다(프로필 변경과 같습니다).
- 근거 청크 수를 10 이상으로 둔 경우 한 문서에서 가져오는 대목이 최대 4개에서 청크 수의 절반까지로 늘어납니다.
- "계약금액 부분 수정해줘"처럼 무엇을 어떻게 바꿀지 말하지 않은 문장은 문서를 고치지 않고 글로 답하거나 어떤 글인지 묻습니다. 문서의 글을 바꾸려면 "'A'를 'B'로 바꿔줘"처럼 따옴표로 말하세요.

## 확인한 것

- Rust 테스트 601 · clippy · 형식 검사, 웹 타입 검사 · 단위 테스트 383 · 브라우저(모의 백엔드) E2E 149, 플래너 골든셋 226문장 중 218(96.5 %).
- 예산이 기본값이면 모든 모델 · 백엔드 · 프로필의 로드 크기가 종전과 같다는 것을 테스트로 고정했습니다.
- 실제 모델(Gemma 4 E4B Q4_K_M, CPU)로 "다듬어줘 / 수정해줘" 문장의 해석을 쟀습니다: 앞 대화가 없는 7문장 7/7, 앞 답변이 있는 6문장 6/6. 잰 것은 문장 해석까지이고, 다듬은 글의 품질은 재지 않았습니다.

## 확인하지 못한 것

- 큰 컨텍스트(30K ~ 131K)로 실제 로드되는지, 그때의 VRAM과 속도. 이 환경에는 GPU가 없고 실제 엔진으로 큰 컨텍스트를 올려 보지 않았습니다.
- 엔진이 켜진 상태에서 예산을 바꾼 뒤 "다시 불러오기"만으로 적용되는지(엔진 재시작이 확실한 방법입니다).
- 실제 Windows 설치본에서의 동작. 체크리스트 "1.0.6" 절에 적었습니다.

## 알려진 제한

- 모델이 지원하는 최대 컨텍스트가 실제 한도입니다(E4B 131,072, 12B 262,144). 그보다 큰 예산은 그 안에 들어가는 만큼만 쓰입니다.
- "다듬어줘"만 말하면 가장 최근의 답변이나 요약을 다듬습니다. 열어 둔 문서의 한 부분("이 조항 다듬어줘")을 다듬는 것은 아직 그 글을 함께 보내야 합니다.
