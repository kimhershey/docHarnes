# DocuLens 0.7.0 계획 — 7건 일괄 (2026-11-10)

사용자 지시(0.6.0 게시 직후):

1. 프로젝트의 문서와 참고자료를 하나로 통합.
2. 문서 작성 항목에서, 본문의 문단을 추가하거나 제거할 수 있도록 수정.
3. 문서 작성 화면에서 스크롤이 이상한 곳에 생성되는 현상 수정 필요.
4. 양식 추출항목 화면에서 양식 등록이 동작하지 않음.
5. 문서 작성 화면에서 재생성 지시 항목을 변경하여 특정 절 수정/추가 및 전체 수정이 가능한 AI 어시스턴트를 호출하도록 변경.
6. AI 어시스턴트 화면에서 채팅을 세션별로 선택 및 추가할 수 있도록 수정.
7. 특정 화면에서 이름이 긴 파일 추가 시 UI 배율에 따라 박스 밖으로 탭이 길어지는 현상 수정.

기능(1·2·5·6)이 섞여 있으므로 **마이너 0.7.0**. 브랜치 `release/0.7.0`은 `release/0.6.0` 끝(0491812)에서 분기했다(0.6.0이 아직 `main`에
완전히 병합되지 않음 — PR #20은 범프 커밋만). 범프 커밋 d7c1f3e는 `Cargo.lock`·SBOM을 포함해 CI 7개 잡을 통과했다(0.6.0의 교훈).

> **상태(2026-11-10)**: §1 전부 구현 — 코어·셸 직접, 프런트는 포크 3개(워크트리)로 병렬 작업 뒤 병합(ab369f1·0026c15·a64b3b1); 코드 리뷰 10건 중 8건 반영. 검증·CI·빌드 기록은 `docs/HANDOFF.md` "0.7.0" 절.

### 1.5 재생성 지시 → 초안 어시스턴트 (5)

**절(section)의 정의**(TS·Rust 공통): `body`를 수준 ≤ 2인 heading 블록에서 자른 구간. 첫 블록이 그런 heading이 아니면 앞부분이 1절(제목 없음).
서수는 1부터. 제목이 하나도 없으면 본문 전체가 1절.

**요청 계약** — `DraftRequest.revise: ReviseScope | null`(serde `default`, 옛 요청과 호환):

```ts
type ReviseScope = { scope: "section"; section: number } | { scope: "insert_after"; section: number | null; heading?: string | null } | { scope: "whole" };
```

- `section`: 해당 절을 지시대로 다시 쓴다(필드·표·다른 절은 그대로). `insert_after`: 해당 절 뒤(`null`이면 끝)에 새 절을 만든다(`heading`이 있으면 그 제목).
  `whole`: 종전 전체 재생성(`previous` + `feedback`) — 분할 생성에서도 지시를 모든 절 호출에 전달하도록 고친다.
- `previous` = 현재 초안, `feedback` = 지시문(필수, 2,000자 상한은 종전과 같음). 작업은 종전 `JobSpec::Draft` 그대로(작업 종류·진행·취소·완료 경로 재사용),
  진행 단계 이름 `revising`.
- 코어 `generate::draft()`가 `req.revise`가 있으면 `revise()`로 분기: 스키마 이름 `draft_revise`(모양은 `draft_section`과 같은 `{blocks}`), 프롬프트
  `prompts::revise_user`(요청 머리 + 확정 사실(필드·표) + **현재 절 본문** + 앞·뒤 절 요약 + 지시), `parse_body`로 블록화 → 해당 구간 교체/삽입 →
  `validate()` 재실행(이슈 재색인) → `notes`에 "AI 수정(n절 '제목'): 지시" 추가. 결과는 `DraftOutcome`(`sections = 1`).
- 모의(`mock-generate.ts`): `revise`가 있으면 결정적으로 반영(절 교체 본문에 지시문 반영 문구, 새 절은 제목 + 문단 1, 전체는 종전 `buildDraft`).
- 화면: 좌측 요청 폼 아래의 "재생성 지시" 패널을 **초안 어시스턴트** 패널(`generate-revise-panel`)로 교체 — 범위 선택 `generate-revise-scope`
  (전체 / 각 절 "n. 제목 다시 쓰기" / 각 절 뒤 "새 절 추가" / 끝에 새 절 추가), 지시 입력 `generate-revise-instruction`, 실행 `generate-revise-run`,
  진행·취소는 생성과 같은 작업 추적, 이력 `generate-revise-log`(지시 → 결과 메모). 편집기의 절 제목 행에 "AI 수정" `draft-section-revise-${i}`(범위를 그 절로
  맞추고 입력에 포커스). 실행 중 편집기 잠금은 종전과 같음.
- 플래너 op **`revise_draft`**(compose 계열; 0.6.0 규칙 "화면 기능 = op"): `{ draft_id?: string, scope, section?, heading?, instruction }`. `draft_id`가 없으면
  `UiPlanContext.draft_id`(문서 작성 화면에 열린 초안)를 쓰고, 그것도 없으면 clarify. 실행은 저장된 초안을 읽어 위 `revise` 호출 → 저장 → 페이로드 `{draft}`
  (결과 카드가 `draft_document`처럼 문서 작성 화면으로 넘김). 규칙: "3절 다시 써줘 …", "결론 절 추가해줘", "초안 전체 격식체로" 등; 골든셋 +3.

### 1.6 어시스턴트 채팅 세션 (6)

**저장**(코어, 마이그레이션 `0012_chat_sessions.sql`, `SCHEMA_VERSION = 12`):

```sql
CREATE TABLE chat_sessions (id TEXT PRIMARY KEY, title TEXT NOT NULL DEFAULT '', title_auto INTEGER NOT NULL DEFAULT 1,
                            created_at TEXT NOT NULL, updated_at TEXT NOT NULL);
CREATE INDEX chat_sessions_updated ON chat_sessions(updated_at);
CREATE TABLE chat_messages (session_id TEXT NOT NULL REFERENCES chat_sessions(id) ON DELETE CASCADE, seq INTEGER NOT NULL,
                            payload TEXT NOT NULL, created_at TEXT NOT NULL, PRIMARY KEY (session_id, seq));
```

- 메시지 `payload`는 프런트의 `Message` JSON 그대로(코어는 내용을 해석하지 않음; 자동 제목만 `payload.role == "user"`의 `text` 앞 40자).
- 명령(`src-tauri/src/commands/knowledge.rs`, 코어 `knowledge/chat.rs`): `chat_sessions_list() -> ChatSessionSummary[]`,
  `chat_session_create(title?) -> ChatSessionSummary`, `chat_session_rename(id, title)`, `chat_session_delete(id)`,
  `chat_messages_list(session_id) -> {seq, payload, created_at}[]`, `chat_message_put(session_id, seq, payload)`(upsert; `updated_at` 갱신·자동 제목).
  `ChatSessionSummary = { id, title, title_auto, created_at, updated_at, message_count }`.
- 보존: 유지보수 작업의 "대화 기록"(`chats_days`) 파기에 `DELETE FROM chat_sessions WHERE updated_at < cutoff` 추가(메시지는 CASCADE).
- 모의: `mock-knowledge.ts`(또는 `mock-chat.ts`) 워크스페이스별 localStorage.

**프런트**:

- `stores/assistant.ts`: `{ workspace, sessions, activeId, messagesBySession, pendingUiActions, nextId }`; 선택자 `messages = messagesBySession[activeId] ?? []`;
  `push(sessionId, m)`·`patch(sessionId, id, f)`는 **요청 시작 때 잡은 세션 id**로(스트리밍 중 세션을 바꿔도 다른 세션에 쓰지 않음); `newSession()`(빈 세션이 있으면
  재사용), `select(id)`, `rename`, `remove`, `hydrate(workspace)`(목록 + 활성 세션 메시지). 메시지에 `createdAt`. 복원 보정: `pending` 답변 → 취소 표시,
  `executing` 플랜 → `pending`. 저장은 `push` 뒤와 메시지가 확정되는 `patch` 뒤에만(스트림 델타는 저장하지 않음).
- 첨부(`attachments.ts`)는 세션별 `attachedBySession`; 한 번 쓰는 핸드오프 필드는 전역 유지. `pendingUiActions`는 워크스페이스 전역(정확히 한 번 실행).

  행 `assistant-session-${id}`(`data-active`, 제목 말줄임, 상대 시각), 행 메뉴(이름 바꾸기 `assistant-session-rename`, 삭제 `assistant-session-delete` + 확인).
  `md` 미만에서는 헤더의 세션 선택 `assistant-session-picker`. 헤더 "새 대화" 버튼은 `assistant-new-chat`과 같은 동작.
- i18n `assistant.sessions.{title,new,rename,delete,delete_confirm,untitled,empty}`; `assistant.memory.hint` 문구 갱신.
