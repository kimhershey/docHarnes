## 1. PPTX 변환본이 PowerPoint와 다르게 보이는 문제

사용자 보고(0.8.2): 문서함에서 PPTX를 열면 **배경이 안 보이고, 차트와 표가 제대로 그려지지 않는다.**

DocuLens에는 PowerPoint 엔진이 없습니다. `documents/convert/pptx.rs`가 파일의 XML을 읽어 내부 모델(`DocModel::slides`)로 옮기고, `convert/html.rs`가 HTML로 다시 그린 뒤 WebView2가 PDF로 인쇄합니다.
아래 세 가지는 이 자체 리더가 구현하지 않은 부분이며, 새 의존성 없이 보강할 수 있습니다.

| # | 항목 | 지금 동작(코드 확인) | 할 일 |
|---|---|---|---|
| 1-1 | 배경 | `pptx::background_of`가 단색(`bgPr/solidFill`, `bgRef` 테마 색)만 읽는다. 그림 배경(`bgPr/blipFill`)·그라데이션은 버린다. `slide_shapes`는 슬라이드 자신의 도형만 그려서 마스터·레이아웃에 놓인 배경 그림·로고·띠가 나오지 않는다. | `Slide.background`를 색 / 그라데이션 / 그림으로 넓힌다. 마스터 → 레이아웃 → 슬라이드 순으로 자리표시자가 아닌 도형을 그린다(`showMasterSp` 반영). |
| 1-2 | 표 | `pptx::table`이 글·병합·열 너비·첫 행 머리글 여부만 읽는다. 셀 채움, 테두리, 행 높이, 표 스타일을 버리고 회색 선(0.5pt)과 회색 머리글로 통일한다. 기본 표 스타일은 머리글이 진한 바탕에 흰 글자라서, 바탕을 버리면 머리글이 잘 안 보인다. | `tcPr`의 채움·테두리(`lnL/R/T/B`)·세로 정렬·여백, `tr@h` 행 높이. `tableStyleId` — `ppt/tableStyles.xml`의 정의와 PowerPoint 기본 스타일(Medium Style 2 계열: 머리글·줄무늬·첫 열, 스타일의 글자색). `model::Cell`에 채움·테두리 필드 추가, HTML 출력 반영. |
| 1-3 | 차트 | `graphicFrame`의 차트는 "차트"라고 적힌 점선 틀(`ShapeKind::Placeholder`)만 남긴다. | 관계(rels)로 `ppt/charts/chartN.xml`을 찾아 저장된 값(`c:numCache` / `c:strCache`)으로 막대·가로 막대·선·영역·원형 차트를 SVG로 다시 그린다(제목, 범례, 축 이름, 계열 색은 테마 색). 그 밖의 종류는 데이터 표로 대신한다. 차트의 항목·값을 `DocModel::blocks`에도 넣어 검색·질문에 잡히게 한다. |

- **범위 밖**: 그림자·반사 같은 효과, 글꼴 대체로 생기는 줄바꿈 차이, 3D·복합 차트의 동일 재현, SmartArt, 애니메이션·전환. 구형 PPT(97–2003)는 글만 읽는 지금 상태를 유지한다.
- **검증**: 배경 그림·마스터 장식·스타일 표·차트를 담은 샘플 PPTX를 만들어 변환본(PDF → PNG)을 눈으로 확인하고 단위 테스트를 둔다. 실제 PowerPoint 화면과의 대조는 사용자 PC에서 한다(체크리스트 항목 추가).
- **순서 제안**: 표 → 배경 → 차트(차트가 가장 크다). 토큰을 아껴야 하면 표·배경만 먼저 내고 차트를 뒤로 미룬다.

## 2-1. 기존 문서를 서식 그대로 고쳐 저장하기 — 검토 결과 (2026-11-12, 실행 전)

**결론**: HWPX · DOCX · PPTX는 가능하다. 문서를 다시 만들지 않고 **원본 파일의 XML을 그대로 둔 채 고친 곳의 글자만 바꾸는 방식**이면 글씨체·크기·표·그림·쪽 설정이 원본 그대로 남는다.
이 방식은 이미 등록 양식 채우기(`generate/fill.rs`: zip의 다른 부분은 그대로 복사하고 본문 XML만 고쳐 쓰며, 표의 행을 본떠 늘린다)에 쓰고 있어 새 의존성이 필요 없다. HWP(바이너리)와 구형 DOC · PPT는 같은 수준으로는 어렵다.

지금 있는 "글자 수정"(`edit_text`, 뷰어의 글자 고치기)은 앱이 뽑아 둔 쪽 글(DB)만 고치고 원본 파일은 건드리지 않는다.

| 형식 | 서식 유지 수정 | 비고 |
|---|---|---|
| HWPX | 가능 | 고친 문단의 줄 배치 캐시(`hp:linesegarray`)를 지워 한컴오피스가 다시 배치하게 해야 한다(지금 코드는 다루지 않음 — 한컴오피스에서 확인 필요). |
| DOCX | 가능 | Word가 열 때 다시 배치한다. 목차·쪽 번호 같은 필드는 Word에서 갱신해야 한다. |
| PPTX | 가능 | 글상자·표의 글자. 글이 늘면 상자를 넘칠 수 있다(자동 맞춤 설정에 따름). |
| XLSX | 가능(셀 값) | 공유 문자열·셀 XML을 고친다. 수식 결과는 Excel이 다시 계산한다. |
| HWP 5.0 | 어렵다 | 압축된 레코드 스트림이라 글자 수·글자 모양 위치·줄 배치를 함께 고쳐야 하고, 쓸 수 있는 라이브러리(소스 공개 의무 없음)를 알지 못한다. 권장: 한컴오피스에서 HWPX로 저장한 뒤 수정. |
| DOC · PPT · XLS(구형) | 하지 않음 | 새 형식으로 저장한 뒤 수정. |
| PDF · 스캔 | 범위 밖 | 원본 서식을 가진 편집 대상이 아니다. |

수정 종류별로 서식을 맞추는 방법:

| 수정 | 방법 |
|---|---|
| 글자 바꾸기 | 그 글자가 든 run의 글자만 바꾼다. 글씨체·크기·색은 run에 붙어 있어 그대로 남는다. |
| 문단 추가 | 바로 앞(또는 지정한) 문단을 본떠 문단 속성·글자 속성을 그대로 쓰고 글만 넣는다. |
| 표의 값 · 행 추가 · 행 삭제 | 셀 글자만 바꾸거나, 기존 행을 본떠 넣는다(양식 채우기에 있는 방식; HWPX는 행 번호를 다시 매긴다). |
| 그림 교체 | 그림 파일만 바꾸고 틀(크기·위치)은 둔다. |
| 새 표 · 새 그림 삽입 | 문서 안의 기존 표·그림을 본뜰 수 있을 때만. 없으면 기본 서식으로 들어가 원본과 달라질 수 있다(뒤 단계). |

풀어야 할 문제:

1. **고칠 위치 찾기** — 화면에 보이는 것은 변환본(PDF)이라 원본 XML의 어느 문단인지 알아야 한다. 변환할 때 문단마다 원본 위치(부분 이름 + 문단 순번)를 기록해 두고 그 문단을 겨냥한다. 기록이 없는 기존 문서는 "바꿀 글이 문서에 한 번만 나올 때만 적용, 여러 번이면 묻기".
2. **쪼개진 글자** — 한 낱말이 서식이 다른 여러 run에 나뉘어 있을 수 있다. 문단의 글을 이어 붙여 위치를 찾고, 바뀐 글은 첫 run에 넣고 나머지에서 지운다(첫 run의 서식을 따름).
3. **다시 배치되는 것** — HWPX의 줄 배치 캐시, 목차·쪽 번호·상호 참조. 앱은 값을 고치지 않고 오피스 프로그램이 열 때 갱신하게 둔다.
4. **손대지 않는 문서** — 변경 내용 추적이 켜진 문서, 암호·배포용(보호) 문서, 전자서명 문서(서명이 깨짐), DRM으로 감싼 파일(읽을 수 없음).

안전장치: 원본을 덮어쓰지 않고 수정본을 새 파일로 저장해 같은 문서의 새 판(`doc_versions`)으로 등록한다. 적용 전에 바뀌는 문장의 전·후를 보여 주고 확인받는다. 저장한 뒤 앱의 리더로 다시 읽어 의도한 곳만 바뀌었는지 자동으로 대조한다.

단계 제안(1.0.0 안에서):

1. 글자 바꾸기 + 새 판 저장 — HWPX · DOCX · PPTX.
2. 문단 추가·삭제, 표 행 추가·삭제(본뜨기).
3. 어시스턴트 명령("3조의 납품 기한을 12월 31일로 바꿔줘": 모델이 문단별 고친 글을 제안 → 전·후 미리보기 → 적용)과 뷰어에서 고친 글자를 원본에 반영.
4. 그림 교체, XLSX 셀.
5. (보류) HWP 바이너리 직접 수정 — 따로 조사한 뒤 결정.

확인하지 못한 것: 수정한 파일을 한컴오피스 · Word · PowerPoint가 문제없이 여는지는 이 환경에서 볼 수 없다(사용자 PC 체크리스트로 확인). `linesegarray`를 지웠을 때 한컴오피스가 다시 배치하는지는 실제 프로그램으로 확인해야 한다. 외부 자료는 조회하지 않았다.

| 4-1 | 답·설명 합치기 | `explain`을 `answer`에 흡수한다. 가리킨 구절은 `answer`의 선택 항목(예: `selection`)으로 두고, 지시문 갈래는 실행기가 고른다. 0.8.2의 `guard::explain_what_was_said`는 필요 없어진다. `summarize`·`compare`는 남기되 "질문 형태면 answer"를 지시문·검사로 분명히 한다. |

| 4-3 | 참고 자료 지정 한 길로 | 셋 중 하나만 모델에게 보이게 하고 나머지는 그쪽으로 돌린다(안: `manage_reference` add / remove를 기준으로, 프로젝트를 말하면 그 프로젝트의 참고 자료 묶음). |
| 4-4 | "실행할 것이 없다" 정리 | `noop`을 모델 문법에서 빼고(대화 답변 또는 `clarify`만 남김) 보정 코드를 걷어낸다. |
| 4-5 | 나머지(4 ~ 10, 12번) | 보고된 오동작이 없다. 실제 모델 측정에서 혼동이 보이는 것만 줄인다. |

주의할 점:

- 문법과 지시문이 바뀌므로 **실제 모델 재측정이 필요**하다(골든셋 기대값의 op 이름도 바뀐다 — `eval/golden/planner.json`, 기준선 다시 만들기).
- 저장된 대화의 플랜(JSON)과 사용자가 저장한 것에 옛 op 이름이 남아 있다. 읽을 때는 옛 이름을 계속 받아들인다(serde 별칭 또는 읽기 변환).
- 함께 바꿀 곳: 규칙 경로(`rules.rs`), 프리라우터, 실행기, `src/features/assistant/opSpecs.ts`, 모의 백엔드(`mock-planner.ts`), 화면의 op 라벨(i18n), 문서의 "op 63개" 표기.

## 5. 어시스턴트가 고른 작업을 표시할지 정하는 설정

사용자 지시(2026-11-12): "AI 어시스턴트는 무슨 작업을 선택했는지 출력할 지 출력하지 않을지 를 설정 항목에 추가하고, 하네스에도 AI 를 통해 해당 설정을 추가할 수 있도록 해줘."

| # | 할 일 | 내용 |
|---|---|---|
| 5-1 | 설정 항목 | 설정에 "어시스턴트가 고른 작업 표시" 스위치를 추가한다(코어 `settings`의 필드 + 설정 화면 + `ko.json` / `en.json`). 키 이름 안: `ui.show_assistant_steps`(켜짐 / 꺼짐). |
| 5-2 | 화면 | 꺼져 있으면 플랜·결과 카드에서 단계 목록(고른 동작 이름·인수)을 숨기고 요약과 결과만 보여 준다. 켜져 있으면 지금처럼 보여 준다. |
