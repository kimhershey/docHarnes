사용자 지시: **"A 실행, 위에 검토했던 GUI 검토는 제안내용대로 정리. 그리고, 사이드 바의 메뉴들을 AIDP 및 오피스에이전트의 용어들을 참조하여
사람이 사용하는 SW 용어로 변경."** 검토 원문은 세션 기록(2026-11-10 GUI 검토, 지식 저장소·프로젝트 통합 검토)이고 핵심은 아래에 다시 적었다.

## 2. A안 설계 (프로젝트 = 업무 문서 + 참고 자료)

- **데이터(마이그레이션 0010)**: `collections`에 `kind TEXT NOT NULL DEFAULT 'reference'`(`reference` | `project`), `project_id TEXT`(프로젝트 참고 자료 묶음은
  프로젝트당 1개, `kind = 'project'`), 인덱스. 기존 컬렉션은 모두 `reference`·`project_id NULL` = 공통 참고 자료의 묶음. `watch_folder`는 더 이상 쓰지 않음(열 유지, UI·타입 제거).
  `project_documents`는 그대로 업무 문서. 프로젝트 삭제 시 그 참고 자료 묶음도 삭제(문서는 라이브러리에 남음).
- **범위 계산**: `SearchScope.project_id` 추가. `scope_doc_ids`: project_id가 있으면 허용 집합 = 업무 문서 ∪ 프로젝트 참고 자료 ∪ 공통 참고 자료(활성 묶음)
  (다른 조건과는 교집합). `knowledge::mod`에 `SearchScope::project(id)`. 어시스턴트·근거만 찾기·문서 작성 `use_knowledge`·플래너 `answer{knowledge}`가 같은 규칙.
  근거 칩에 "업무 문서 / 참고 자료" 구분(검색 결과의 `role`로 판단).
- **역할 표시**: 참고 자료 묶음에 넣는 문서는 `role = knowledge`로 표시(기존 "지식 베이스에 추가"와 같음), 업무 문서로 넣으면 `work` 유지. 둘 다인 문서는 참고 자료 쪽이 우선.
- **플래너**: `ExplainScope::Collection` → `Reference`(공통 참고 자료) 유지하되 이름만, `add_to_project`에 `as_reference: bool`(기본 false) 추가,
  자연어 "참고 자료로/지침으로 넣어줘" 규칙, 골든셋의 컬렉션 문구 교체. `scope.filter.project_id`는 그대로.
- **셸 명령(계약)**: 기존 `knowledge_collections`·`collection_save`·`collection_delete`·`knowledge_add_docs`·`knowledge_remove_docs`·`knowledge_ingest`는 유지하고
  `Collection`에 `kind`, `project_id` 필드 추가, `collection_save` 입력에 `project_id?`. 신규 `project_reference_group(project_id) -> Collection`(없으면 생성).
  `knowledge_search`·`knowledge_ask`·플래너 UI 컨텍스트의 scope에 `project_id?` 추가. 홈 전용 명령은 문서함 띠가 재사용(변경 없음).
- **프런트**: 프로젝트 목록 맨 위 고정 카드 "공통 참고 자료"(가상 id `common`, 묶음 목록·적재·드롭). 프로젝트 상세 탭 **문서 · 참고 자료 · 규칙 · 결과(검사·관계·리포트) · 설정**.
  라이브러리 "지식 베이스에 추가"/"프로젝트에 추가"/"프로젝트로 분류" → 하나의 대화상자 **"프로젝트에 넣기"**(대상: 프로젝트 또는 공통 참고 자료, 종류: 업무 문서 / 참고 자료; 자동 분류 제안 버튼 포함).
  적재 마법사는 이 대화상자의 "파일에서 가져오기" 단계로.

## 3. GUI 정리 (검토 제안 그대로)

| 영역 | 변경 |
|---|---|
| 질문 입구 | 검색 화면 삭제, 어시스턴트에 "근거만 찾기" 토글(모델 호출 없음, 하이브리드/키워드/의미 선택 유지). 질문 테스트 패널은 설정 > 참고 자료(고급) |
| 어시스턴트 | "해석: 모델/규칙(구형)" 토글을 설정 > 일반 > 고급으로. 범위 선택지 3종 |
| 참고 자료 | 기본 화면 = 묶음 + 문서 + 적재. 버전·용어집·답변 기록·색인 통계·임베딩 실행은 설정 > 참고 자료(고급) |
| 프로젝트 상세 | 탭 5개(결과 탭이 검사 결과·관계 그래프·리포트 버튼을 포함). "정리·내보내기" 탭은 설정 탭으로 |
| 문서함 | 집계 바 삭제(어시스턴트 질문으로 대체). 다시 렌더·재스캔·inbox 감시는 카드/빈 공간의 우클릭 메뉴와 설정 > 처리로. 상단 "오늘 할 일" 띠 |
| 양식·추출 항목 | 설정 탭. "양식 등록"이 기본 동작, 새 항목·자연어 만들기/수정은 편집기 안 보조 버튼 |
| 정리/내보내기 | 메뉴 삭제, 문서함 버튼으로 진입, 이력 탭은 작업 현황으로 |
| 설정 | 8탭 → 7탭(위 표). 테마·단축키·정보는 일반 탭의 섹션 |
| AI 모델 | 설정 탭. 추천 모델 카드 + "받기/불러오기" 기본, 등록 표·발견 표·수동 티어·엔진 상세는 고급 접기 |
| 상태바 | AI 엔진 상태(모델 이름 포함) + 작업 배지만 |
| 드롭 대상 | 사이드바에서는 문서함(가져오기)·프로젝트·문서 작성만 |

## 4. 작업 순서·분담

1. 코어·셸(A안 데이터·범위·명령·플래너) — 직접.
2. 프런트 묶음 1(사이드바·용어·문서함 띠/정리 진입·어시스턴트 범위·근거만 찾기·설정 탭 재편·상태바·드롭 대상) — 포크 에이전트.
3. 프런트 묶음 2(프로젝트 목록·상세 탭·공통 참고 자료·프로젝트에 넣기 대화상자·참고 자료 화면·작업 현황 이력 탭·모의 백엔드 명령) — 포크 에이전트.
4. E2E·단위 테스트 재작성, i18n ko/en 패리티, 문서(설계 §3.14·§3.15 합본 안내, RUN-GUIDE, 체크리스트, HANDOFF, 릴리스 노트) — 분담 후 통합.
5. 전체 검증 → 커밋·푸시 → CI → Lite 빌드(아티팩트) → 사용자 확인 후 게시.

## 5. 유지되는 것·한계
- 용어집·임베딩 모델·색인은 워크스페이스 전역. 여러 프로젝트에 걸친 질문은 "전체" 범위.
- 0.4.0 워크스페이스는 마이그레이션 0010만 거치며 데이터 이동 없음(기존 컬렉션 = 공통 참고 자료 묶음).
- 플래너 골든셋 100건은 유지(컬렉션 문구만 참고 자료 문구로).
