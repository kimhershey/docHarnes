# DocuLens 0.4.0 계획 — 중국계 LLM 제외, Gemma 4 + EmbeddingGemma 2 탑재 (2026-11-10)

사용자 지시: **"0.4.0 버전을 준비. 모든 중국계 LLM 을 제외하고, 새로운 8GB 이내 LLM 모델을 준비하여 소프트웨어에 탑재.
기존과 같은 방식으로 모델과 임베딩을 다운로드하도록 변경."**

이 문서는 후보 조사 결과, 선정 근거, 레지스트리 설계, 코드·문서 영향 범위, 작업 순서와 사용자 PC 확인 항목을 정리합니다.
경로는 저장소 루트 기준이고 0.3.0(커밋 772782f) 코드를 기준으로 읽었습니다. 라이선스 원칙은 `docs/LICENSE-POLICY.md`
(소스 공개 의무가 없는 라이선스만, 커뮤니티·연구용 라이선스 금지)를 그대로 따릅니다.

## 2. 선정: Gemma 4 — 근거와 리스크

**근거**
1. **라이선스**: Gemma 4부터 Apache-2.0(Gemma ≤ 3은 커스텀 Gemma Terms로 정책상 금지). EmbeddingGemma 2도 Apache-2.0.
2. **엔진 호환**: 이미 고정된 llama.cpp b12066(2026-11-03)이 `gemma4`·`gemma4-assistant`·`gemma-embedding2` 아키텍처와
   `gemma4v`/`gemma4uv` 비전 프로젝터, Gemma 4 전용 채팅 파서(PEG)와 `--reasoning off`를 모두 포함합니다 → **엔진 팩·CUDA 팩 재빌드 불필요**.
3. **8 GB 사다리**: E2B(3.1~5.1 GB) → E4B(5.0~7.1 GB) → 12B Q4_K_M(7.1 GB)로 CPU~24 GB+ 티어를 한 패밀리로 덮음(같은 템플릿·프롬프트).
4. **VRAM**: Gemma 4의 KV는 슬라이딩 윈도우(512/1024) 층이 5:1 비율이고 마지막 N층은 KV를 공유해 32K 컨텍스트에서도 수백 MB 수준.
   E2B/E4B의 층별 임베딩(PLE) 표(≈1.3~2.5 GB)는 llama.cpp가 `TENSOR_READ_LAZY`로 호스트에서 읽어 GPU 상주분이 파일 크기보다 작음.
5. **품질**: Google 공식 보고에서 E4B/12B가 동급 최상위(문서·차트 벤치 포함); 한국어 OCR은 공개 수치가 없어 §9에서 골든셋으로 검증.

**리스크와 완화**

| 리스크 | 완화 |
|---|---|

| 이미지 토큰 상한 **1,120**(Qwen 2,200~3,072보다 낮음) | 48 px/토큰 기하(패치 16 × 풀링 3)에 맞춰 페이지를 2.58 MP까지 렌더(실질 해상도는 Qwen 1,500 토큰(1.5 MP)보다 높음); 잔글씨 프로파일은 1,120 고정 |

## 3. 임베딩: EmbeddingGemma 2 — 근거

- Apache-2.0, Google, **ggml-org 공식 GGUF**(공급망 신뢰), b12066 day-0 지원(`gemma-embedding2`), Gemma 4와 토크나이저 공유.
- 768차원·8K 입력: 현재 청킹(목표 500·최대 800 토큰, `MAX_EMBED_CHARS` 2,000)을 그대로 쓸 수 있음(e5의 512 토큰 제한 없음).
- 접두어 규약(공식 모델 카드): 질의 `task: search result | query: {text}`, 문서 `title: none | text: {text}` → 레지스트리 `defaults`에
  `query_prefix`/`document_prefix`로 넣고 `knowledge/embed.rs`가 붙임(bge-m3는 접두어 없음 → 모델별 설정으로 일반화).
- 풀링 `mean`(공식), `pooling` 기본값 변경. 차원이 1024→768로 바뀌므로 기존 `chunks_vec`는 `ensure_vec_table`이 모델 변경을 감지해
  자동으로 비우고 재임베딩합니다(이미 구현된 경로).
- 유사도 임계값 `min_vector_similarity`(기본 0.5, bge-m3 기준)는 EmbeddingGemma 2의 분포에 맞게 사용자 PC에서 재확인(§9).

## 5. 코드 영향 범위

### 5.1 코어 — 모델 인식·프리셋 (`crates/doculens-core`)
- `modelstore.rs` `SUPPORTED_ARCHS`: `("gemma4", "gemma4-doc-v1")`, `("gemma-embedding2", "embedding")` 추가. Qwen 아키텍처 항목은 **드롭인 호환을 위해 유지**(레지스트리에서만 제외).
  드롭인 기본값(`image_min_tokens`/`image_max_tokens`)은 아키텍처별 비전 기하에서 가져옴.
- `engine/presets.rs`: `image-min-tokens`를 전역 `[*]`(1,024 — Qwen 전용 하한)에서 **모델 섹션**으로 옮기고 `defaults.image_min_tokens`를 씀;
  `image_max_tokens_for`는 모델의 상한(`defaults.image_max_tokens`, Gemma 4 = 1,120)을 넘지 않게 클램프(FinePrint 3,072 → 1,120).
  `--reasoning off --reasoning-budget 0`은 유지(Gemma 4 템플릿도 `enable_thinking` 지원 — 소스 확인).
- `pipeline/image.rs`: `VisionGeometry { px_per_token, max_tokens }`(Qwen 32 px/4,096 · Gemma 4 48 px/1,120)로 토큰 계산·축소를 일반화;
  `pipeline/run.rs`·`vlm.rs`·셸 `pipeline_bridge.rs`가 로드된 모델의 아키텍처로 기하를 고름(`VisionGeometry::for_arch`).
- `pipeline/prompts.rs` `template_kwargs()`: 그대로(`enable_thinking: false`는 두 템플릿 모두 수용), 주석만 갱신.
- `gguf.rs`/`memory.rs`: Gemma 4 KV 추정 — `attention.sliding_window`, `sliding_window_pattern`(bool 배열), `shared_kv_layers`,
  층별 `head_count_kv` 배열, `key_length`(전역)·`key_length_swa`를 읽어 전역층 × ctx + SWA층 × min(ctx, window) 로 계산;
  `per_layer_token_embd.weight` 바이트를 `host_resident_bytes`로 분리해 GPU 추정에서 뺌. `synthetic_gemma4_metadata` 테스트 헬퍼.
- `registry.rs` 테스트·`required_files_text` 테스트를 새 id로.

### 5.2 코어 — 지식 베이스·플래너
- `knowledge/embed.rs`: 모델별 접두어(`query_prefix`/`document_prefix`) 적용, 주석(bge-m3 → EmbeddingGemma 2);
