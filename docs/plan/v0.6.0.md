# DocuLens 0.6.0 계획 — AI 어시스턴트가 소프트웨어 기능 전부를 수행 (2026-11-10)

사용자 지시: **"설정 내용 변경이나 파일 추가, 변경 등의 소프트웨어 수행 기능을 AI 에이전트가 모두 수행할 수 있도록 … 0.6.0 으로 실행하자. 완료 후에
0.6.0 릴리즈도 만들어."** 브랜치 `release/0.6.0`(`release/0.5.0` 끝에서 분기 — 0.5.0이 아직 `main`에 병합되지 않아 직전 버전 브랜치에서 잇는다).

> **상태**: 구현 중. 코어·셸은 직접, 프런트(UI 액션·설명·모의·E2E)는 포크 에이전트.

## 0. 요약

| 축 | 0.5.0 | 0.6.0 |
|---|---|---|
| 플래너 op | 43개 | **62개**(신규 19 + 확장 3). 화면에서 되는 일은 모두 명령으로도 됨 |
| 설정 | `set_setting` 7키 + 전용 op | **설정 카탈로그 44키**(`ui.*`·`models.*`·`processing.*`·`cache.*`·`privacy.*`·`notifications.*`·`knowledge.*`·`generation.*`) — 옛 7키는 별칭 |
| 모델 호출 | 한 번(op 43개 표 ≈ 5.5K 토큰) | **2단계**: ① 계열 선택(≈0.5K) → ② 그 계열 op 표로 플랜(≈2~3K). 실패 시 종전 1단계로 |
| 안전장치 | 확인 카드·되돌리기 | 그대로 + 삭제·네트워크(다운로드)·엔진 정지·워크스페이스 닫기·파기는 확인 카드 필수 |

원칙: 원본 파일은 바꾸지 않는다(회전·글자 수정은 캐시·DB·사본). OS 창(파일 선택)은 모델이 못 열므로 경로를 말하거나 끌어다 놓은 파일을 쓴다.

## 1. op 계약 (프런트·모의·골든셋이 그대로 따름)

실행 주체: **core** = `planner::exec`(미리보기·확인 카드 포함), **ui** = `OpKind::runs_in_ui` → 프런트 `commands.ts`가 IPC 호출.
표기: `?` = 선택, `[]` = 목록, `enum[...]` = 문법 열거. 범위(scope)는 종전 규칙(선택·현재 문서·폴더·필터·프로젝트).

### 1.1 문서 (core)
| op | 파라미터 | 확인 | 비고 |
|---|---|---|---|
| `import` (확장) | `source: inbox\|folder\|files`, `path?`, **`paths?: []`**(files일 때 필수, 절대 경로), `recursive?`, `auto_pipeline?` | folder·files | `files`는 끌어다 놓거나 적은 경로 |
| `rotate` | `degrees: int(90\|180\|270)`, `pages?: int[]` | — | 범위 문서의 쪽 이미지 회전(원본 불변) |
| `rerender` | `dpi?: int(72~600)` | — | 범위 문서 다시 렌더 |
| `split` | `boundaries?: int[]`(새 문서가 시작하는 쪽, 2 이상), `every?: int` | ✓ | 범위 문서 1개 → 새 PDF 문서들 |
| `merge` | `name?: str` | ✓ | 범위 문서 2~20개 → 새 PDF 문서 |
| `set_title` | `title: str` | — | 범위 문서 1개 |
| `edit_text` | `find: str`, `replace: str`, `pages?: int[]` | ✓ | 범위 문서의 쪽 글자 찾아 바꾸기(이력·재색인; 미리보기에 일치 수) |
| `set_role` | `role: enum[work, knowledge, form]` | — | 업무 문서 / 참고 자료 / 양식 표시 |

### 1.2 참고 자료 (core)

| op | 파라미터 | 확인 |

## 2. 2단계 플래닝 (`planner/prompts.rs`·`schema.rs`·`llm.rs`)

- **계열**(`OpFamily`): `ask`(search·answer·summarize·explain·compare) · `documents`(import·classify·set_doc_type·ocr·extract·validate·review·tag·rename·move·organize·delete·rotate·rerender·split·merge·set_title·edit_text·set_role·open) ·
  `reference`(manage_reference·define_term·set_version·reindex·set_role) · `projects`(create/update/delete_project·add_to/remove_from_project·manage_template·classify_projects·define_rule·check_consistency·request_supplement) ·
  `forms`(define_schema·register_form·manage_schema) · `compose`(draft_document) · `output`(aggregate·export) · `system`(set_setting·set_theme·set_language·set_model·set_profile·set_retention·set_inbox_watch·manage_model·engine·workspace·maintenance·job·undo·redo·help·open).
  `clarify`·`noop`·`open`은 모든 계열에 포함.
- **1단계**: 짧은 시스템 프롬프트(계열 8개 + 한 줄 설명 + 워크스페이스 요약) → 문법 `{"families": [enum, enum?]}`(최대 2, 복합 문장용). 토큰 ≈ 0.5K.
- **2단계**: 선택된 계열의 op 표 + 그 계열 few-shot 2~3개 + 컨텍스트 블록으로 종전 플랜 문법(선택 계열 op만 허용하는 `plan_schema_for`). 검증 실패 재질의 1회는 그대로.
- **폴백**: 1단계 오류·빈 결과 → 종전 1단계(전체 표, 티어 축소) 경로. 컨텍스트 예산이 전체 표를 담고도 남으면(≥ 12K) 1단계 생략 가능하나 기본은 항상 2단계(정확도).
- 규칙(RulesFirst)·프리라우터·골든셋은 그대로; 새 op 중 자연스러운 문구는 규칙 추가(§4).

## 3. 작업 분담

1. **코어·셸(직접)**: op 열거·스펙 표·문법·검증기·실행기·미리보기·부작용/확인 분류, 설정 카탈로그, 2단계 프롬프트, 규칙·테스트·골든셋(+20건)·기준선 재생성. 셸: `UiPlanContext` 변경 없음.
2. **프런트(포크)**: `types.ts`(Op 유니언·OpKind)·`opSpecs.ts` 미러·`describePlan.ts`·`commands.ts`(ui op 실행: set_setting 범용·manage_model·engine start/stop·workspace·maintenance)·결과 카드 페이로드 표시·i18n·모의 플래너 규칙·모의 백엔드·E2E `agent.spec.ts`.
3. **문서**: RUN-GUIDE §4(명령 목록), 체크리스트 "0.6.0", 릴리스 노트, HANDOFF, 설계 부록 D 안내.
4. 전체 검증 → CI → Lite 빌드 → **Release v0.6.0 게시**(사용자 지시) → `main` 병합은 사용자.
