## 2. 양식 등록 → 문서 1~N개로 AI가 추출 스키마를 자동 저장

**현재** (`crates/doculens-core/src/pipeline/forms.rs:348-424`, `src/features/schemas/FormRegisterDialog.tsx`)
- 문서 **하나**만 받음(선택·드롭·`?register=<id>`). PDF/이미지는 **첫 렌더 쪽 이미지 + 전체 쪽 텍스트(7,000자 컷)**로 VLM 1회
  (`Stage::FormFields`, 메타스키마 문법 `schema::metaschema()`), 오피스 형식은 구조 규칙(라벨 셀·빈 셀·표 머리행)으로 먼저 뽑고 비면
  텍스트만 VLM. 모델 오류 시 텍스트 규칙 대체(`derive_from_text`, 커밋 ffb8618).
- 셸 `pipeline_bridge::form_derive`(`:268-278`)는 **작업(job)이 아니라** 인터랙티브 게이트 안의 동기 호출이고, 모델이 **이미 로드된
  경우에만** 사용(자동 로드 없음). 진행률·취소 없음.
- 결과는 저장되지 않은 `SchemaDraft` → 편집기에서 사용자가 저장(`form_register`: 스키마 저장 + 샘플 문서 `role=Form`, `doc_type=slug`).
  규칙(`rules`)은 항상 비어 있음. 쪽 2장 이상의 이미지는 보지 않음.

**변경안**
- **작업화**: `JobSpec::SchemaDiscovery { doc_ids, name_hint }`(`jobs/mod.rs:103-135` 변형 추가, 레인 Engine) +
  셸 `JobKind::SchemaDiscovery`(`src-tauri/src/jobs.rs:35-73`) + `planner_bridge::run_spec` 분기(`:345-366`) + 프런트 `JobKind`
  (`src/lib/types.ts:525`). 모델은 `vision_model(app, true, …)`로 **자동 로드**, `gate.batch_begin()`·`checkpoint`로 다른 작업과 조율,
  문서·쪽 단위 진행률, 취소 가능.
- **코어 `forms::discover(docs, hint)`**:
  1. 문서별로 쪽 선택(첫 쪽 + 표가 있는 쪽, 최대 3쪽) → 쪽마다 이미지(`image::prepare`, 스테이지 토큰 예산) + 그 쪽 텍스트로
     `FormFields` 호출 → 쪽별 메타스키마. 한 메시지에 이미지를 여러 장 넣는 도우미(`user_message_with_images`)는 추가하되 8K 컨텍스트
     티어를 고려해 기본은 **쪽당 1회 호출**.
  2. **병합**: 키 정규화(`schema::known_key`/`suffix_key`), 문서 ≥ ⌈n/2⌉에 나타난 필드만 채택(모두에 나타나면 `required`), 종류는
     다수결(충돌 시 String), enum 옵션 합집합(≤12), 표는 열 이름 합집합(≤20), 라벨은 최빈값, 이름·doc_type은 문서별 제안의 다수결에
     사용자 힌트 우선.
  3. (n ≥ 2일 때) 텍스트 전용 **정리 호출 1회**(`Stage::NlSchema`, 병합 결과 + 문서별 요약 → 최종 메타스키마)로 라벨·설명을 다듬음.
  4. **규칙 추론(결정적)**: 합계류 키(`grand_total`/`supply_total`/`items.amount`)가 있으면 합계 규칙, `period_start/end`면 날짜 순서
     규칙을 `KNOWN_RULES` 안에서만 붙임(모델이 규칙을 만들지 않음).
  5. 결과는 **저장하지 않고** 편집기로 넘김(현행과 같음). 저장은 사용자가 편집 뒤 저장 버튼을 눌렀을 때만: `form_register`가 샘플 문서
     전부를 `role=Form`·`doc_type=slug`로 표시하고 `pipeline://changed{schemas}`를 보냄.
  6. **이름 중복**: 편집기가 이름을 바꿀 때마다 `pipeline_schema_name_exists(name, excluding_id)`(새 명령, 대소문자·공백 무시 비교)를
     호출. 이미 있으면 **알림 팝업**으로 "같은 이름의 스키마가 있습니다 — 예: `{name} (2)`"를 제안하고 이름 입력란에 포커스. 그래도
     같은 이름이면 **저장 버튼 비활성** + 입력란 아래 오류 문구(`schema_name_duplicate`). 린트(`schema::lint`)에도 같은 코드를 추가해
     백엔드 `save_schema`가 중복 이름을 거부(이중 안전장치).
- **UI**: 대화상자를 다중 선택(체크 목록 + 여러 문서·파일 드롭, `?register=id1,id2`)으로, 이름 힌트, 작업 진행 카드(문서별 상태·발견
  필드 수), 완료 후 편집기 열기(저장 전 상태, 이름 중복 검사 포함). 라이브러리 일괄 메뉴에 "선택 문서로 양식 만들기"(`library-register-form`),
  플래너 op `register_form`에 `doc_ids[]`. 오류 코드 재매핑(`commands/pipeline.rs:162-176`)에 `job` 경로 추가.
- **모의·검증**: `mock-pipeline.ts deriveForm` 다중 문서 병합 흉내, E2E "문서 2개 드롭 → 자동 저장된 스키마가 목록에 뜨고 병합 필드 수
  표시", 코어 테스트(병합 다수결·required·enum 합집합·규칙 추론·취소).
- **리스크**: 4B 모델의 표본 간 편차(임계값 ⌈n/2⌉로 흡수), 긴 문서(쪽 선택 3장 제한), 시간(문서 n × 쪽 p × GPU 약 5초).
- **결정(2026-11-10)**: 자동 저장 없음(편집 후 저장 버튼), 이름 중복은 팝업으로 변경 제안, 같은 이름이면 저장 비활성. 같은 doc_type의

     빼면 그 사본만 삭제(휴지통), 문서 삭제 시 모두 삭제. 저널에 `copy`/`remove_copy` 항목을 추가해 되돌리기 가능.
  4. **외부에서 사본을 고친 경우**: 재검사가 해시 불일치를 "사본 변경됨"으로 표시하고 "새 버전으로 가져오기 / 대표본으로 덮어쓰기"를
     제안(자동 동기화는 하지 않음).

## 10. (추가 보고) 문서 라이브러리에서 수정한 파일의 저장·되돌리기

**보고**: "수정한 파일의 되돌리기 및 저장이 정상적으로 동작하지 않음". **코드 확인 결과, 뷰어의 수정은 모두 앱 내부 데이터만 바꾸고 원본
파일은 건드리지 않습니다.** 따라서 사용자 지시대로 **우선은 그대로 둡니다.** 상세:

- 글자 레이어 수정(Enter로 확정)은 `documents_edit_page_words` / `documents_add_page_words`가 **즉시** `.doculens/workspace.db`의
  `pages.text`·`pages.layout`(`text_source = manual`)에 쓰고 지식 색인을 다시 만듭니다. 별도 "저장" 단계가 없고(토스트 "n쪽 텍스트를
  저장했습니다") 원본 PDF·이미지는 바뀌지 않습니다(툴팁 "원본 이미지는 바뀌지 않으며 …"). 그래서 탐색기의 파일이 그대로인 것은 **정상**입니다.
- 회전 저장(`documents_rotate_page`, `import.rs:881`)도 페이지 캐시 이미지를 다시 렌더하고 DB의 `pages.rotation`·레이아웃만 갱신합니다.
  원본은 그대로입니다.
- **되돌리기(Ctrl+Z, `/되돌리기`, 어시스턴트 되돌리기)는 파일 조작 저널(정리·이름 변경·삭제)만 되돌립니다.** 글자 수정 뒤 Ctrl+Z를 누르면
  "되돌릴 작업이 없습니다"가 나오거나 **관계없는 마지막 파일 배치가 되돌려질 수 있습니다** — 보고된 "되돌리기가 동작하지 않음"의 원인입니다.
  글자 수정에는 되돌리기가 아예 없습니다(이력 패널의 "이 값으로 복원"은 추출 **필드 값** 이력만 복원).
- 디자인 원칙(원본 불변·DB 경로 상대 저장)상 원본 파일에 수정을 써넣는 기능은 권하지 않습니다. 고친 글자를 파일로 갖고 싶으면 이미 있는
  **검색 가능 PDF 내보내기**(수정된 텍스트 레이어 포함)를 쓰면 됩니다.

**0.3.0에 넣을 작은 항목(7, 1일)**: 쪽 글자 수정 이력 표 `page_text_history(document_id, page_no, before_text, before_layout, after…,
at)` + 뷰어 상단 "글자 수정 되돌리기 / 다시 실행"(해당 쪽, 최근 20건) + Ctrl+Z가 **뷰어에서 마지막 동작이 글자 수정이면 그것을** 되돌리고
아니면 종전대로 파일 저널을 되돌리도록 범위 분리 + 이력 패널에 "글자 수정" 목록(원래 글자로 복원). 원본 파일은 계속 불변.
